# tests

The harnesses that hold the shell layer and the terminals to a spec. `HACKING.md` ("Checking the terminals") describes them for people.

- A ratchet (`mise run forks`, `costs`, and the facts and gaps of `parity` and `compat`) fails on a worse number, and fails on a better one until `--update` records it, so a hot path only ever loses processes and a cost only ever drops. A temp file made again inside a folder a terminal watches fails `costs`.
- `mise run compat` opens each installed terminal's window and is not part of `ci`. Add a case to `tests/compat/cases.zsh` before claiming a terminal supports a feature, and put its expectation in both `expect.tsv` and `expect-linux.tsv`. `--update` writes what was measured and never a skip over a pass or a fail. A model assumption becomes a case before the model leans on it. The Linux builds and Konsole run in Docker.
- `mise run parity` (part of `ci`) walks every journey in `tests/parity/journeys.ts` in a model of each terminal and holds it to one spec, `facts.tsv`. A cell that misses the spec needs a row in `gaps.tsv` (terminal, fact glob, `cannot`, `layer` or `deferred`, reason), or the terminal's one `@capability` row where it lacks a capability; a gap row that covers a fact it does not explain fails until it is narrowed. A journey whose facts moved is walked again up to twice before it counts.
- `mise run walk` walks the model at random and is not part of `ci`. A failure is shrunk and printed as a journey to paste into `journeys.ts`.
- The harnesses keep every process off the user's real terminals: shims for `ps`, `pkill`, `defaults` and `dbus-send` stand in. Never exercise ttheme end to end against the real `~/.config` or `~/.zshrc`; use `mise run sandbox`, a throwaway home. `--warp` and `--terminal-app` wire the user's own apps, so they refuse `--mine`.
- `mise run bench` and `tests/latency.zsh` measure shell latency through a pty and are not part of `ci`; `shell:check` runs the same harness and asserts only orders. Never measure with `time zsh -lic exit`. A pty session ends through `stop`, never a bare `zpty -d`.
