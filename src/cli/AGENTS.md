# src/cli

The verbs and what orchestrates them: `sync`, `init`, `refresh`, `update`, the marketplaces.

- `verbs.ts` is the one list of commands; the parser, `ttheme help` and the shell's completion read it, and `palettes.zsh` carries every verb but the setup ones. A palette is never a command (`ttheme use <palette>`). There is no `preview` or `browse` command: the bare `ttheme` is the hub, and `browse` stays in `VERB_SPECS` as a `hidden` verb only because the hub's tab runs it. `ttheme auto`, `light` and `dark` are shell verbs with no node side (`__tt_mode`).
- A verb's `about` is sentence case, and its head up to the first ` — ` (`headOf`) is a short phrase that fits one line in `ttheme help`. `more` verbs are left out of `help` and listed by `help all`.
- A slug typed alone resolves through `find` (`src/store/available.ts`): an exact full name, else the one palette with that slug. The shell resolves the same way without a fork (`__tt_resolve`). There is no prefix matching, deliberately.
- `ttheme info` is what a bug report carries, and `.github/ISSUE_TEMPLATE/bug.yml` asks for its output: a row added to `info` is added to that field's description too. The shell hands `info` `TTHEME_ZSH` and `TTHEME_ADAPTER`, since inside tmux the CLI sees only `TERM_PROGRAM=tmux`.
- A verb that takes `--json` prints one object on stdout (`emit`, `answer.ts`), a shape that only gains fields. Every verb exits by `EXIT`: 0 done, 1 failed, 2 nothing changed, 3 invalid input (`UsageError`, `InputError`), 4 a network failure (`Unreachable`, thrown by `reach`).
- A mode change goes through `sync`, which `ttheme auto`, `light`, `dark`, `config` and preview's `Mode` row run. `sync` rewrites a file only when its content changed, `palettes.zsh` included. `palettes.zsh` (`palettesZsh`, `emit-shell.ts`) declares every table even when empty: a zsh lookup with a `/` in its key on an undeclared name is fatal.
- `autoRefresh` (`refresh.ts`) runs in `runCli` before `add`, `marketplace`, `default`, `on` and `off`, and never from the shell layer. What it adds beside another verb is advice, so it goes through `advise` to stderr and only when stderr is a terminal, since the shell layer captures stdout. `ttheme update` and Browse's closing report are the verbs' own output and stay on stdout. A refresh is one `Outcome` (`attempt`), and `failureLine` is how a failure reads everywhere.
- `TTHEME_AUTO_UPDATE=off` or a `CI` environment stops the daily release check and `autoRefresh`, never `ttheme update`; the tui, parity, `bin:check`, latency and sandbox harnesses set it.
- A repository marketplace has auto-update off until it is switched on, and `ttheme` and a folder never have it; `installed.json`'s `updates` holds only the switches that differ from that default (`withMarketplaces`). A source may pin a ref (`owner/repo#v1`).
- `ttheme update` updates ttheme first: when `newerRelease` finds a newer one and this is the installed CLI (`runsInstalled`), `upgradeTo` runs `init --yes` at an exact version through the runner `installed.json` names (`npx --yes …@<x.y.z>`, or `bunx …@<x.y.z>`), in a fresh folder of its own (`askDir`; `bun info` reads no registry without a `package.json` there), then hands the rest of the run to the new CLI with `TTHEME_UPDATED` set, so the old process never syncs over what the new one wrote.
- `npx` or `bunx …@latest init` is the only way a new version reaches `~/.config/ttheme`, and `init` records which ran it (`runnerOf` over `npm_config_user_agent`; npx when it was neither) for the release check, `upgradeTo` and every command a message names. Over an existing install `init` is the update path: it offers to update and keep everything (`planUpgrade`), `--yes` does so without asking, and "set it up again" (`planAgain`) carries every setting it does not ask again.
- `init` refuses to install without a Node.js the tab layer can run (`layerNode`): under bunx with no Node.js, Bun puts a `node` of its own first on PATH, which the layer's shell never sees.
- `parseIndex` and the marketplace readers drop what they do not recognize and strip control and bidi characters, since every field comes from someone's repository. The index's shape (`Listed`, `ListedPalette`, `ListedWork`) only gains fields.
- `ttheme palette` (`palette.ts`) is what the ttheme-palette agent skill runs, and `skills/ttheme-palette/` (its `SKILL.md` and the `references/` it sends an agent to) is its one source. A change to those steps that an older copy of the skill would get wrong raises `SKILL_FORMAT` (`src/store/agent-skills.ts`) and the skill's "skill format above" number together, since `init` never refreshes a copy another tool installed.
