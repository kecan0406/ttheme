# src/tui

The runtime under every Node screen (Browse, init's picker, the palette editor, find) and the parts they share. Preview is the one full-window screen not on it: it stays in zsh (`shell/preview.zsh`). `HACKING.md` ("Working on the TUIs") and `.claude/rules/tui.md` are the reference for roles, marks, keys and the mouse, and the `tui` skill maps a screen to its files.

- A screen is a model whose `view` returns its rows. The runtime (`terminal`, `keys`, `screen`, `zones`, `field`, `motion`, `ansi`, `style`, `pending`) imports no part, and the shared parts (`parts`, `bar`, `help`, `hub`, `notice`, `qr`) import no screen. A new file here is a screen until `.oxlintrc.json`'s lists name it.
- `Terminal` owns the terminal while a screen is up, and puts back in reverse every mode a screen set on every way out: its `finally`, a signal, an error thrown anywhere, process exit. Modes a program around it already set (preview around find or Browse) are `assume`d: set, never put back.
- `Keys` is the one input decoder, so no screen reads `esc` out of half an arrow. `lineStep` is the one table that turns `up`, `down`, `ctrl-j` and `ctrl-k` into a line step, and a screen with no filter passes `letters` to take `j` and `k` too: where a filter takes typed text, `j` and `k` are text.
- `Screen` writes only the rows that changed, in one synchronized write, and a frame costs its `view()`, so keep `view` cheap. Every width goes through `cells` (`src/core/text.ts`), never the string-width package, so a line never wraps. `edit` (`field.ts`) is the one line editor, and clack stays for inline questions only.
- Every SGR a screen writes comes from `style.ts` (`ROLES`, `SURFACES`, `MARKS`), and the shell layer's from `TTHEME_SGR` and `TTHEME_MARKS`; `style.test.ts` fails on an SGR or a mark written anywhere else. A screen's own chrome never names a color: its accent is the terminal's slot 6. A palette's own colors (swatches, scenes, the mock terminal) stay hex. What stays in the scrollback uses roles and slots only. `fit` and `clip` close what the cut text opened, never with a full reset.
- Every full-window screen takes the mouse as well as the keys, and every mouse action has a key that does the same; init's picker takes none. A view marks what is clickable with `zone(target, text)`. A press selects, and only a release over the zone pressed acts, so a screen that closes on a click has read the release first.
- ctrl+c leaves every Node screen; Browse with something staged and the editor with something changed ask first.
- ttheme's mark `>ω` has one source, `src/core/mark.ts`. A terminal shows it only in color, at most once a screen and never moving; without color (`NO_COLOR`, a pipe, `TERM=dumb`) there is none. `--version`, `info`, an error, any other notice and the spinners never carry it.
- A CLI verb that waits on the network says what it waits on through `pending`: one dim spinner line on stdout, shown only after 300 ms and only on a TTY.
- Browse is split by what each piece owns (`browse/`): `browse.ts` (keys, mouse, layout), `staged.ts`, `network.ts`, `review.ts`, `search.ts`, `form.ts`, `panel.ts`, `draw.ts`, `types.ts`. Each is handed what it needs (a `…Host` of fields and closures, or the other pieces), never Browse. Browse fetches by itself unless `TTHEME_MARKETPLACE_LOOKUP` is `off`, which the tui and parity harnesses set.
- The palette editor never changes the terminal's own colors: only its mock terminal is drawn in the draft, in explicit colors, and its own rows keep the terminal's. It measures its draft with `gateRows` and parses it only to save, neither through `memo`.
