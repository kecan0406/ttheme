# Konsole

The shell layer's, the wiring's and the picture model's general rules are in `terminals.md`; these are what only Konsole does.

## Conventions

- Konsole (`KONSOLE_VERSION`, which Konsole's session sets, so Yakuake and the Dolphin and Kate panels too; 23.08.5 measured under Xvfb, its source read up to 26.04) draws the background and foreground an OSC 10/11 sets, about 20 ms later, and no OSC 12 or 17; it never draws an OSC 4 — it keeps the colors only to answer OSC 4 queries, which therefore report what an OSC 4 set rather than what it draws (`#b21818` after a scheme switch drew `#f47e6b`, measured), so compat's `wear` leaves ansi 1 to `wear-ansi`'s screenshot in any terminal whose `ansi-painted` failed in the same run; its bare OSC 104/110/111/112 resets do nothing (`110;` and `111;` reset from 25.12); and it parses an OSC 10/11 color with Qt's `QColor`, which reads `#rrggbb` and never `rgb:`, so a TUI restores it in hex (`hex`). A palette's 16 colors therefore reach a tab only through a color scheme, and Konsole holds a scheme as it read it for as long as any tab shows it, reading a name no tab shows from disk again (`_colorSchemes` keeps weak pointers; compat's `scheme-held`, `scheme-released` and `scheme-fresh` measured all three on 23.08, and `scheme-picture` its wallpaper): `sync` (and `pictures`, which `refreshPictures` runs on every picture change) writes each palette's scheme — all 30 entries (`schemeLines`, `src/terminals/emit/konsole.ts`: intense from the brights, faint halfway to the background) and the palette's picture as its wallpaper (`wallpaperLines`: `Wallpaper=` the conf's file, `FillStyle=Crop` for cover and `Adapt` for contain, `Anchor=` the position, `WallpaperOpacity=` the opacity; empty while the picture is off) — twice into `$XDG_DATA_HOME/konsole`: as `ttheme-<stem>.colorscheme`, the stable name the `ttheme-<stem>.profile` beside it names (the scheme, the cursor, `Name=ttheme · <palette>`, `Parent=` the user's default — `konsoleBase` — or `FALLBACK/`; written for every listed palette and the startup one, and dropped once a palette is no longer installed), since Konsole loads its profiles once per process, and as `ttheme-<stem>.<hash>.colorscheme`, the first 8 hex digits of the text's SHA-1 (`versionOf`), whose name changes with its content; older versions are deleted, and `palettes.zsh` carries the current ones as `TTHEME_KONSOLE_SCHEMES` (`<stem> <hash>` pairs, `schemeVersions`), so every shell rereads them at its next prompt or focus. The konsole adapter wears an installed palette with one `OSC 50 ColorScheme=<versioned name>;UseCustomCursorColor=true;customCursorColor=<cursor>` (`__tt_scheme`, which falls back to the stable name when the versioned file is gone; lowercase: Konsole's own `CustomCursorColor=` shortcut sets the cursor only for the moment) and never an OSC 11 in the same burst, and remembers what the tab shows (`TTHEME_KONSOLE_SHOWN`, the payload, and `TTHEME_KONSOLE_NAME`, the palette whose picture it carries): `__tt_reloaded` sends the payload again whenever the version of what the tab wears moved, so a picture tuned or a tone changed in another tab reaches it, and a new tab moves off the profile's stable scheme onto the versioned one before its first prompt (no process; the colors are the same, and no tab is then left holding a stale stable scheme a later tab would share). Colors no palette holds — a tone being tuned in preview's panel, a palette of an unwired Konsole — go through a view scheme the shell writes itself (`__tt_konsole_view`: the same 30 entries, faint by the same rounding, `Description=ttheme · <palette>`, no wallpaper) as `ttheme-view.<pid>.<n>.colorscheme`, keeping the two latest (the one Konsole may still be about to read after its 20 ms debounce) and deleting both at exit (`__tt_konsole_bye`, a `zshexit` hook); browse and init's picker do the same from the CLI (`konsoleLive`, `src/terminals/terminal.ts`: `ttheme-view.<10 hex of the content>.colorscheme`, three kept, all swept when it ends) once the shell hands it what the tab shows as `TTHEME_KONSOLE_LOOK` (`__tt_cli_env`), copying that scheme's wallpaper lines so a hover keeps the tab's own picture, and restore with that payload. An unwired Konsole therefore paints too, through view schemes, and resets to the user's own look, which the adapter reads from `konsolerc`'s `DefaultProfile` and the profiles it names, following `Parent=` (`__tt_konsole_own`, no process); it takes no default and keeps none. A reset goes to the look a new tab opens with: the startup palette's scheme, or while off the user's own (`TTHEME_KONSOLE_BASE`, the `layer` value `baseLook` reads through the base profile's parents). Before the hub hands the tab to browse, `__tt_pv_leave` puts on the tab's own look again, so browse copies the tab's picture rather than preview's last hover. Konsole loads its profiles and `konsolerc` once per process, so `point` sets `[Desktop Entry] DefaultProfile` in `konsolerc` (giving `konsoleBase` back while off, removing the key when there was none) and then calls `setDefaultProfile` on every running Konsole over D-Bus (`dbus-send`: each `org.kde.konsole-<pid>`, its first `/Windows/<n>`), checking `defaultProfile` after — a Konsole started before that profile existed needs a restart, and ttheme says so. It reports focus changes (mode 1004) though it answers no DECRQM at all, so compat's `focus-report` skips there and `focus-event` measures it — `xdotool` moving focus away and back on the Xvfb display — and the layer binds focus reporting; and since an open tab never reads a new default profile, the konsole adapter's `__tt_takes_default` switches a tab that never painted to the new startup palette's scheme itself (`__tt_osc_reset`). It passes compat's kitty graphics cases with Ghostty's layer order (every negative `z` under the cells with a background of their own and over the wallpaper; EL leaves images), so preview's layers, tuning and find work as in Ghostty (`__tt_bg_cells` through `CSI 16t`, crops through the source rectangle), and after preview saves a picture `__tt_pictured_konsole` refreshes the schemes through the CLI and `__tt_bg_refresh` puts the new version on the tab. Konsole 23.08 draws a wallpaper only on a translucent window, which it makes only while a compositor runs (24.02 draws it always), so the compat container starts `xcompmgr` on its Xvfb display. It opens an OSC 8 link only where the profile allows escaped links (`AllowEscapedLinks` under `[Interaction Options]`, off by default), which ttheme leaves to the user, since it writes colors only — so preview and `ttheme add` mark a post as a link only where the default profile, or one it inherits through `Parent=`, allows them (`__tt_links` reading `__tt_konsole_links` once a shell, `konsoleLinks` in `src/terminals/terminal.ts`; `TRAITS.konsole.links` stays false). The sandbox (`--konsole`, Linux) runs it on its own Xvfb display and D-Bus session (`dbus-run-session`), with `XDG_DATA_HOME` scrubbed, so nothing reaches the user's Konsole.
