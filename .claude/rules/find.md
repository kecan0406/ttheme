# find: booru search, own pictures, backdrops

## Conventions

- `meta.booru` is the character's danbooru tag and, with `[meta.booru_sites]` for the sites that name the character otherwise (one tag, a list find ORs with `~` — moebooru only, since danbooru and zerochan count tags — or `[]` for a site that has none and is not asked; found by md5 — on zerochan, which has no md5 search, through its redirects and suggestions, kept when danbooru tags at least half of the files it shares as this character, or with too few shared when zerochan names the palette's series — and checked by the palette skill's `names.ts` and `tags.ts`; 26 of 139 palettes name zerochan's own, and `dorothy` has none there), the only thing ttheme knows about finding its art: `preview`'s tab opens `find` (`src/find.ts`, a hidden CLI verb), and so do the palette editor's `p`, a drop and a paste (`findFor`, on an entry parsed from the draft being edited, with a `Start` that takes the paste or reads the clipboard at once; `new` and `edit` list the booru pictures it installed as `[[picture]]` on save and drop them all when cancelled, `shelfFor`), which searches that tag live on the sites in `SITES` (`src/booru.ts` — danbooru at `shima.donmai.us`, konachan through its safe-only `konachan.net`, yande.re, and zerochan), each read at the ratings `TTHEME_FIND_RATING` lists — `safe` by default, asked for in the query (`rating:s` on Moebooru, `rating:g,…` on danbooru, which does not count it against its two-tag limit; zerochan keeps none, so `parseZerochan` rates a post `g` unless a nudity tag makes it `q`) — with the tag groups `TTHEME_FIND_BLOCK` names (nudity, underwear; both by default) dropped, and installs through `src/backdrop.ts`. What makes a good backdrop is judged from the tags each post carries — a konachan, yande.re or zerochan post also borrows the tags danbooru holds for the same file, one `md5:` list per page (`fetchLent`, `src/booru.ts`), never a request per post — so `TTHEME_FIND_SOLO` drops a post only when it knows its headcount (`Post.solo`, danbooru's or zerochan's own, or borrowed). The `s` panel's advanced page (`a`, or enter on the `Advanced ›` row `pageOf` puts after each page's rows, at index `settings.length`; `Setting.advanced`) holds the filters every site is asked for in its own terms — `Site.narrow` turns a `Narrow` (lowest score, shortest side, PNG only) into query parts (danbooru's `score:`, `width:`, `height:` and `filetype:` and zerochan's `dimension:` pseudo-part, which `tagsOf` does not count, while an `order:` still does) — and `eligible` checks every post again on arrival, a site that cannot keep one (`scored`, `guesses`) noting it; each row carries an `about` the panel shows under the rows and its `default` (`settingDefault`, `src/wiring.ts`, read through `initial`), named at the panel's right edge while it differs — the panel's size is set once from both pages at their widest (`widest`, `held`), so no change of page, value or typing moves it; its title, labels, button and `about` are sentence case, the values, site names and tags stay as `config.zsh` spells them, and key hints stay lowercase, a number or text row (`entry`) takes typing (`typeKey`), and the panel counts what each site holds for the unsaved values (`pending`, `countPending`, a moment after each change) — a zerochan count means nothing once a filter or second tag is on (`Site.counts`), and danbooru answers a count it gave up on with `null` (`parseCounts` → NaN, never 0); the all tab mixes the sites `TTHEME_FIND_SITES` ticks, and `TTHEME_FIND_HIDE` drops the kinds `hidden` finds by tag. The same list hands over danbooru's copy (`Post.mirror`): such a post's original and 360 px preview come from `cdn.donmai.us` (`fileOf`, `previewOf`, which name the site to ask), the same bytes faster than yande.re's and zerochan's servers (a 25 MB yande.re original, measured: 6.4 s → 2.2 s), while the post, its cache paths and its install stay the site's own. The default `fit` order ranks each fetched page (`src/fit.ts`) in two steps — every post by its tags, then as many as the next screens need by their preview's palette colors too — and appends it; the queue is looked at only as far as the next screens (`ahead`) and reordered only while still off screen, so tiles never move under the cursor and no preview is fetched for a page nobody scrolls to. A session keeps every page it fetched, so switching tabs or between `fit` and `newest` asks nothing. Kin is settled when a post arrives, never by where it lands on screen (`src/works.ts`): the same file (md5, pixiv page) keeps the larger copy; a set (one uploader, one size, in a row as the site lists it), a parent's family, a source citing another post or file, or a preview dHash within 2 bits at the same ratio folds into the tile already shown. Measured: a 64-bit dHash of the previews cannot tell an expression variant from a re-encode, so a near shape only folds, never drops, and a konachan crop of a yande.re post differs in ratio, so only its source links it. danbooru.donmai.us is blocked by hostname on some networks (Korea), so danbooru is asked at `shima.donmai.us`, the name Danbooru's own retired `sonohara` and `hijiribe` redirect to (its pages name `danbooru.donmai.us` canonical, and in 2018 its owner pointed blocked users at the other donmai names); `postRef` matches a pasted link by registrable domain, so a `danbooru.donmai.us` post link still opens. zerochan takes the name in words joined by `+` in the path (the data spells them with underscores), more tags after a comma, and `s=fav` for score; it answers an alias with a redirect that drops the query, so `get` follows every redirect itself and puts the query back when the target has none (`redirected`), and a tag it does not know with a 404, which lists nothing (`Site.missing`). Its list names no file: a post danbooru does not hold is found on `static.zerochan.net` by an 8 KB range request for jpg, then png — png first for a cutout — (`locate`, `Site.guesses`), which doubles as the cutout's alpha check, and its previews are the 600 px JPEG, since the list's own are AVIF. preview re-reads the `TTHEME_FIND_*` settings after find returns. A palette names posts only by number, in its `[[picture]]` tables (`site`, `id`, and the framing `size`/`position`/`opacity`) — never an image URL or file; `src/pictures.ts` fetches them on the user's machine through the same filters, cut-out and install as find, and `ttheme new`/`share` fill them in from the pictures the user has up (`heldPictures`, whose framing `tuneOf` reads back from the `.tune.conf` preview wrote; `writeTune` bakes it again with `frameAt`, a port of `__tt_bg_frame`). Palettes that are not one character carry no tag.
- `find` also takes the user's own pictures (`src/attach.ts`). It turns bracketed paste on and reads every paste as file paths or links (`pastedRefs`: backslash escapes, quotes, one per line, `file://` URIs, a raw path with spaces), a burst of typed path-like text as a paste (Warp types a drop instead of pasting it), an empty paste, `ctrl+v`/`alt+v` (anywhere, the search field included) or `v` as a request to read the OS clipboard (`readClipboard`: JXA on macOS, powershell from WSL, wl-paste or xclip — a picture is tried on, a path or link attached, other text goes into the search field, as Claude Code's image paste falls back to text), a focus-in (find turns focus reporting on) as a cue to look at the clipboard's types and say `Picture on the clipboard · ctrl+v uses it` for 8 s (`peekClipboard`, once per macOS `changeCount`), and — when the terminal answers the probe `run()` sends after the cell size (DECRQM 5522, `OSC 72;t=q`, then DA1) — kitty's clipboard protocol (paste events with a one-time password, `CSI ? 5522 h`) and drag-and-drop protocol (`OSC 72`, kitty and iTerm2 3.7), which hand over the picture's bytes (`Grabber`). A picture becomes a post of the pseudo-site `LOCAL` (id from its content hash, below `KEY_SPAN`; `postKey` puts sites outside `SITES` after them), placed in the cache as its own original and preview, and opens in try exactly like a jumped-to post (`single`), so cut-out, try-on and install are the booru path's. Only PNG and JPEG under `MAX_PIXELS` decode; `normalize` sends anything else through `sips` on macOS. A paste while find asks a question, installs or shows a panel is dropped.
- `find` never decodes or encodes an image on its own thread: every decode, resize, tint and PNG write goes through `src/render.ts`, one worker for tiles, one for iTerm2's bands and one for the try view. The worker entry is `import.meta.filename`, which is `src/render.ts` in dev and `bin/ttheme.js` in the bundle, so `src/bin.ts` guards `runCli` behind `isMainThread` and `bin:check` asserts the bundle answers a render message. The try view's worker keeps the last source's ink (`held`, `inked`), so a tuning step never decodes the original again, and `reveal` renders one frame at a time (`presenting`, `again`): a held key shows the frames it gets to and ends on the latest tuning.
- The try view is what installs, down to its tuning: `t` opens preview's tuning panel over it (`tunePanel`, `view.tuning`; ↑↓ field, ←→ and ⇧←→ step, 1-9 place, `=` puts the field under the cursor back and `+` all three, a `↺` marking each field off its default, enter keeps, esc undoes). The tuning (`Tuning`, backdrop's `Framing`) stays while ←→ walk the posts, `tryOn` places the figure with `frameAt` as `writeTune` bakes it (`fill` fields sit at the fill framing, and the worker hands back `fill`, the size at which the figure matches it, where ←/→ cross from fill to sizes), and install passes it to the worker, which writes it with `writeTune` after `installBackdrop` (`aligns` from `installed.json`'s terminals), so preview opens the picture as it was tried. Post, Source and Artist always show under the top line (`credits`, a dim `—` where the post names none, so the rows never move as ←→ walk the posts); `i` puts the rest of the post's details where the scene was (`details`), every row kept the same way. The grid names the artist alone (`—` where none; the uploader is only `i`'s Uploader row) and the score only where the site keeps one. All of them read one post shape: `Post.named`, always present — danbooru's `tag_string_artist/character/copyright`, moebooru's tag types, nothing on zerochan — which `credit` fills role by role where it is empty, together with an empty `source`, `owner` and `posted`: from the md5 list, which asks for those fields and `source` too, and, on a site whose list names none (`Site.credits`: zerochan, whose post page types its tags), from the post's page while the post still names no artist (`uncredited`) — fetched when it or a neighbour is tried (`load`, `preload`), one request per post at a time (`crediting`), and kept in `credits.json` once it names an uploader, which find holds in memory like `probes.json` and `owners.json` (`keep`: each site's JSON caches are read once a session, and `saveKept` writes the changed ones when a search ends and at exit). `sourcePage` names a pixiv file or old illust link by its artwork page (pixiv answers a bare `i.pximg.net` link 403) wherever a source is shown or kept — never in `post.source`, whose `_pN` `sameKeys` needs; install hands the post's artists and that page to the picture (`Original.artist`, `source`), and `src/pictures.ts` borrows the md5 list for a shared picture before downloading it, so its original comes from danbooru's copy through `fileOf` as find's does (measured on konachan 8.6–22.9 s → 0.4–1.1 s, a 22.7 MB zerochan file 23.7 s → 1.3 s), and fetches an `uncredited` post's page beside the download. `infoOf` adds `ratingOf`, which a site asked for no rating (zerochan, a picture of your own) leaves out. Only a site with `Site.uploadedBy` is searched by a mate's uploader. Post and Source are OSC 8 links (`Line.put`'s `link`), as is every post id — on the top line, under each tile (`Tile.page`, none for a picture of your own), in the tuning panel's title and wherever the status line names a post (`mention`, which links the `<site> <id>` it finds there; a post the status waits on is always named that way); find turns no mouse reporting on, so the terminal keeps the click. Every link is marked the way Claude Code marks an artifact link: `⧉ ` (`LINK`, `src/ansi.ts`) before it (`reference`), in the color of the site it opens (`siteColor`) or the accent for a source, and in the all tab that mark takes the place of the site dot `●`, which only a picture of your own keeps. `ttheme add`'s picture lines (`postRef`, `src/pictures.ts`) and preview's tuning title (`__tt_pv_bg_title`) mark a post the same way, only where the terminal opens OSC 8 links (`linkable`, from `TRAITS` in `src/terminal.ts`, which `palettes.zsh` carries to the shell as `TTHEME_LINKS`) and, for the CLI, on a TTY. The scenes (⇧←→, `view.scene`) are `src/scenes.ts`'s `SCENES` — each line `«role»text` runs, a role being `d`, `b`, an ANSI index, `B`+index (bold), `K`+index (that background under ansi0), `s` (selection) or `c` (cursor), and `«w»`/`«n»` keeping a line to panels at least or under `WIDE` columns — which `palettes.zsh` carries as `TTHEME_SCENES` and `TTHEME_SCENE_<n>` for preview; preview hands its scene to find as `TTHEME_SCENE`.
- find draws and installs in the coloring `TTHEME_BG_COLORS` names (`coloringFor`, read at construction like the blur): `tryOn` and `installBackdrop` take it, so the try image is what installs. In original colors the default opacity belongs to the post (its `peak`), not to the palette, so the render worker answers it as `Shown.opacity` and `present` moves `view.untuned.opacity`, and `view.tune.opacity` while it still equals the old default, to it; `render` sends an `opacity` only when the user changed it, so a post walked to draws at its own default and the cache key names it only then. The coloring is `view.coloring`, which starts at that setting and which `c` flips in the try view and in the tuning panel (`recolor`, once the post is shown): the render cache key and the try file's name carry it (`o` in the name, so the other coloring's file is never reused), `view.tune.opacity` goes back to `view.untuned.opacity` so `present` takes the new coloring's default, `present` drops a result drawn in a coloring that is no longer the view's, and install passes `view.coloring` to the worker. esc in the panel puts the three fields back but not the coloring (`TunePanel.coloring` tells it changed, and the opacity then goes to the default instead of the held value, whose scale differs). The panel keeps its three fields — `c` works from any of them and the top line says `own colors` when the picture is not in the palette's tone — and the coloring still can be switched per picture afterwards in preview.
- find lays the palette's background under everything it draws (`cover`: a 1×1 in `entry.background` at `COVER_Z`, below the try view's picture), as preview does, so the picture the terminal shows for another palette never shows through the grid; when preview measured Ghostty's padding it hands it over as `TTHEME_BG_MARGIN` and the cover hangs out over it, placed relative to an anchor. Widths go through `fast-string-width` (`columns`, `clip`), so a Japanese query or tag keeps its columns, and while the query is being typed the cursor rests at its end (`caret`) — a hidden cursor still carries an input method's composition, which Ghostty draws there.
- The grid scrolls by cell rows: `view.top` is still the tile row the cursor keeps in view (`scroll`, which only sets it), and `view.scroll` the cell row drawn at the top of the grid (`gridShape`'s `height` rows from row 2), which `glide` moves toward `top × TILE.height` every 16 ms by 40 % of what is left (a row of 13: 5·3·2·1·1·1, about 85 ms), retargeting on every key, and `snap` sets outright on a resize or another board. A tile the grid's edge cuts — during a glide, and the row the leftover lines show under the last whole one — is placed cropped (`Placement.crop`, the rows cut off its top, set only on a cut tile): through the kitty source rectangle, except in iTerm2 (`cropsInBands`, `src/terminal.ts`), whose Metal renderer flips a source rectangle's `y` and draws no placement that leaves the grid, so the band worker cuts those rows into a PNG of their own (`banded`, `band`). `prebake` asks for the bands of the frame a glide is heading to as it starts, by rendering that frame, so they are ready when it lands; a tile cut in the middle of a glide is left out there rather than waiting on one, and a grid at rest asks for what it lacks. Measured on 3.7.3 at 160×50, 60 frames that re-place 18 tiles cost iTerm2 no more than 60 frames of text alone (about 50 ms against a 20 ms DSR round trip; a newly sent picture 1.5–2.6 ms), and Ghostty took 13–16 ms for 60 frames of 24 tiles, so both glide at the same pace. `flush` rewrites only the rows that changed since the last frame (`screen`, emptied on a resize), inside one synchronized update, and nothing is drawn once the session is aborted — the CLI only sets `process.exitCode`, so a timer left alive would keep the process running. An 80 ms tick runs only while the frame on screen read `view.beat` (`Frame.tick`, set by `beat` as the spinner, the loader and the tips read it), so it stops as soon as nothing moves. Tiles carry no placeholder of their own: while the pump searches and the lines under the last tile row are in view — the whole grid before the first tile, the leftover lines once scrolled to the end — `loader` centers there the stage the grid waits on (`stageLabel`: `Fetching posts`, `Ranking previews by palette colors` while `Board.ranking` holds the `n/m` `looks` counts, then `Checking PNG headers` or `Loading previews` for `Board.stage` `check`), a one-row bar in the cursor color over a selection-tinted track (`bar`: filled to `n/m`, or a segment easing back and forth where there is no count, its end cells half faded) and the sites of the tab, each brightened once its first page arrived (`Board.arrived`, set as each page lands in `round`); it rises out of the background over four ticks (`loaderFrom`, which `flush` sets from `Frame.loader`) and goes the frame the lines fill. This is the site's quiet uwu level and no louder — no kaomoji, sparkles or bouncing type (a set of those was turned down as too much). The footer names the same stage, then `Loading thumbnails · n/m` over the tiles in the scroll window (a failed thumbnail left out as `missing`); until the first posts arrive the line above it rotates the keys only `?` lists (`TIPS`); and the last column is a rail of the rows fetched so far (`rail`), which `gridShape` always leaves free, so a width can hold one tile fewer per row.
- `~/.cache/ttheme/<site>/` keeps what a `find` session paid for — `orig` (the downloaded post), `tile` (the grid thumbnail at the terminal's cell size), `thumb` (the booru preview — danbooru's 360 px variant, since a tile is wider than its 180 px one; preview and tile files carry a hash of the preview URL), `cut` (the Vision cut-out) — plus `probes.json`, `owners.json` and `credits.json`. Only the palette-tinted try images and iTerm2's bands are session-temporary. `sweepCache` trims the four image directories to `CACHE_BYTES`, oldest first, when find exits.
- The `@fill` background (`fillFrame`, `src/backdrop.ts`, shared by `find`'s try screen and install) is made at the shape of the window find ran in (`fillSize`, at most 2560 wide) and placed `top-right`, so a window of another shape later loses its bottom and left, never the head. A figure whose alpha box is at least `STANDS` 12 % transparent stands in it whole from the top — 4 % headroom, 3 % from the right edge, as tall as the larger of 115 % of the window and the height that makes it 40 % of the window wide (so a full body shows its upper half), shrunk to 95 % of the width when wider — which is what the owner's hand tuning converged on (107–128 %, center-right, head kept). Anything less transparent is a wallpaper and covers the window from its top, centred across. The numbers are `PLACEMENT`, which `dist/manifest.json` carries as `placement` beside each palette's `backdrop` tint (`backdropTone`), so the site's backdrop mode (`site/lib/backdrop.ts`, tinting a visitor's own picture in the browser — the site ships no art) draws what ttheme installs. `N` in `@fill-N` is the height of the figure at the window's middle, the focus preview's sizes above 100 % zoom around. Never widen the crop box past the image to make room — `resample` clamps out-of-range samples and streaks the edge pixels; the frame blits instead. The try view and the install draw through the same `draw`/`tryOn` (`src/backdrop.ts`): the ink mask resampled with the Mitchell filter in `src/png.ts` (`resample`, `resamplePlane`, which averages every source pixel when it shrinks and copies a crop at scale 1 untouched), lifted and blurred, so what find shows is what installs — the try view's blur scaled from the fill's width to its own.
- `find` removes an opaque picture's background with the operating system's own segmentation — Vision through `osascript -l JavaScript` (`src/cutout.ts`, macOS 14+), nothing bundled. Measured on six anime pictures, small general models (u2netp, silueta) cut anime badly, the anime one (isnet-anime) is 176 MB, and every in-process runtime is 145–300 MB against a 0.4 MB bundle, so never add an ONNX runtime, model or `rembg` dependency; other systems keep the opaque picture.
