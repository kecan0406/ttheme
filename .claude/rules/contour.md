# Contour

The shell layer's, the wiring's and the picture model's general rules are in `terminals.md`; these are what only Contour does.

## Conventions

- Contour (`contour-terminal/contour`) reads `$XDG_CONFIG_HOME/contour/contour.yml` (made with its defaults at its first start), and beside it two kinds of side file its settings page writes too: `profiles/<name>.yml`, a profile whose body lies over the default profile's values (`mergeGuiManagedSideFiles` in `src/contour/config/Config.cpp`: the default is resolved from `contour.yml` before any side file, so a side profile inherits the user's own font and keys), and `colorschemes/<name>.yml`, a bare color scheme a profile's `colors` names when `contour.yml`'s own `color_schemes` has none of that name; `settings.yml`, the page's global overrides, may name the `default_profile`, applied after the side files. So the wiring owns `profiles/ttheme.yml` (`colors: ttheme.<mode>`, or under `auto` `colors: { dark: ttheme.dark, light: ttheme.light }`, which Contour switches by the system's appearance; `{}` with no startup palette, so the profile is the user's default as it is) and `colorschemes/ttheme.dark.yml` and `ttheme.light.yml` (the startup palette in each mode, `contourScheme`: `default`, `cursor`, `selection`, `normal`, `bright`), beside every palette's `ttheme-<stem>.<mode>.yml`, and edits only `settings.yml`, once: a block holding `default_profile: ttheme` at its top, which keeps a `default_profile` the user had as `# was: …` inside it (`upsertContourDefault`) and puts it back on uninstall (`removeContourDefault`); the settings page rewrites the file without comments, which leaves `default_profile: ttheme` and loses the line, so uninstall then leaves `default_profile: ttheme` naming a profile it removed, which Contour logs and passes over for `contour.yml`'s. A `settings.yml` that is not a block map is left alone and init says so.
- Contour reads its profiles once, when it starts (`live_config` is off by default, its watcher watches `contour.yml` alone, and `settings.yml` cannot turn it on), so a new tab opens on the default profile as Contour read it then: after a new default it shows the old palette. The adapter answers that itself: `__tt_heard` (what a new tab heard at start, or at its recheck) paints the startup palette over any other background while the tab never painted and stays unpainted (`__tt_osc_reset`, which paints the startup palette where the wiring is there, as Terminal.app's does, and unsets `TTHEME_PAINTED`), and `__tt_takes_default` follows a new default the same way. With no startup palette (`off`) a reset returns a tab to the `ttheme` profile as Contour read it, which holds the palette that was the default, so `off` reaches a running Contour at its next start: the one sequence that moves a tab to the user's own profile, `DCS $p <name> ST` (what `contour set profile to` writes; `setTerminalProfile` → `activateProfile` in its session), also resizes the window to that profile's `terminal_size`, so the layer never sends it (parity's `deferred` off rows). A switch of the system's appearance has Contour put every tab back on its profile's colors in the new mode (`updateColorPreference` → `resetColorPalette`), a painted tab's included, and report it under mode 2031; a painted tab takes its palette back at its next command (`__tt_mend`). `sync` touches `contour.yml`'s times whenever one of its files changed, for a Contour the user runs with `live_config`. The detection block names Contour by `TERM_PROGRAM=contour` ahead of Ghostty. Read in its source at 974feaf1 (2026-10-27).
- Contour takes the background an OSC 11 sets (and 111's reset) and answers it, but its window keeps drawing the profile's: the cells of the default background are left to the QML `Rectangle` behind the terminal, bound to `TerminalSession::backgroundColor`, whose `backgroundColorChanged` is emitted only on a profile, appearance or opacity change (contour-terminal/contour#2182, filed 2026-10-27). So every tab ttheme paints, and every tab that follows a new default, shows its text, cursor and ANSI colors on the background of the palette Contour started with (compat's `painted` and `wear-painted` fail on 0.8.0.9335, and so do `follow-default`, `keep-painted` and `reset-worn`, which read the drawn background where a screenshot can be taken: Contour answered the palette each one wanted while it drew the one it started with; parity's `cannot` row lists the facts). The layer still sends OSC 11 as everywhere else, so a Contour that redraws it shows the whole palette with no change here — then measure `mise run compat --linux --update contour`, which moves `BEHAVIOR`'s claims, and drop the row once parity calls it stale.

## Gotchas

- Contour's Linux build is amd64 alone, so `mise run compat --linux contour` runs in an image of its own (`tests/compat/contour.Dockerfile`, `--platform=linux/amd64`, emulated on an Apple Silicon Mac), where GNU tar fails to open files under the emulator (`Cannot open: Function not implemented`), so the image takes Ubuntu's `nodejs` rather than a Node tarball.
