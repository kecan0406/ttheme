# Terminal.app

The shell layer's, the wiring's and the picture model's general rules are in `terminals.md`; these are what only Terminal.app does.

## Conventions

- Terminal.app (`TERM_PROGRAM=Apple_Terminal`) takes every OSC color but ignores the OSC resets, so its startup answer is all 20 colors rather than the background alone (`__tt_hear`, one batched query, which also asks `CSI 14t` where Terminal is wired): `__tt_heard` keeps them as the base `__tt_osc_reset` puts back, and `__tt_start_bg` takes the startup background from them. Init wires Terminal.app on macOS (`src/terminals/terminal-app.ts`): `sync` writes `~/.config/ttheme/terminal-app.js`, a JXA script, and runs it to put a `ttheme · <palette>` profile for every installed palette into Terminal's own settings (`Window Settings` of `com.apple.Terminal`, through `NSUserDefaults`): a copy of the user's own profile (`terminalBase`, the default it found — `Basic` when none) with the palette's 20 colors as device RGB, which Terminal draws exactly as an OSC sets them (measured, the same pixels), the base's background alpha kept, so a translucent profile stays translucent, and the palette's picture as `BackgroundImageBookmark` (an archived `NSURL` bookmark, the key Terminal's own Solid Colors profile carries; a palette without one keeps the base's); each carries `TthemeAt`, set only when something other than the bookmark changed, and the profiles of palettes no longer installed go. Terminal draws a profile's picture stretched over the whole view, ignoring its aspect, above the background color and any background an OSC sets, and composites a see-through pixel over a fixed light grey rather than the background (measured on 2.15: `#cbcbcb` behind a black and a white background alike, and a translucent profile drawn opaque), so a picture goes out laid opaque on the palette's background at its opacity (`lay`: the conf's picture placed by `frameAt` as Ghostty places it, cover or contain at its position, on a canvas of the Terminal window's shape, `canvasFor`, written by `encodeRgb`), as `~/.config/ttheme/terminal-app/ttheme-<stem>.<8 hex of the picture and its framing>.png`, and keeps each picture laid on both modes' backgrounds under those names in `$XDG_CACHE_HOME/ttheme/terminal-app/` (`laidAhead`: the other mode laid once, ahead, and every name no profiled palette's two modes give pruned), so a mode switch writes the cached bytes into the palette's file rather than laying every picture again. The shape is the last `CSI 14t` the layer heard (points, doubled; `$XDG_STATE_HOME/ttheme/terminal-app.window`, `__tt_terminal_shape`), and a first one, or one whose aspect moved past 4%, has the next prompt run `ttheme image … tuned` in the background (`__tt_prompted`, since the adapter loads before `__tt_cli` exists); without one the picture's own shape. Terminal reads a picture when a tab first takes its profile and keeps what it read for each path until it quits — rewriting a file it read changes nothing, even on another profile naming the same path — but resolves the bookmark again every time a tab takes the profile, by the file's identity first: a file written in place and renamed is read again at its new name, and a file removed leaves the profile with no picture (measured, compat's `profile-picture`, `picture-held`, `picture-renamed` and `picture-gone`; a tab taking the same profile again counts). So a picture changed while Terminal runs reaches it without a restart: `lay` writes the new picture into the palette's existing file and renames it (`rewrite`, `src/store/edits.ts`, the one write that keeps a file's identity rather than replacing it, written and then renamed, so a half-written file can only be read under the name being left), `write` keeps a bookmark that still resolves to the file, so `TthemeAt` stays and Terminal still counts the profile loaded, `palettes.zsh` carries each palette's picture as `TTHEME_TERMINAL_PICTURES` (`<stem> <version>` pairs) and each profiled palette's colors and picture as `TTHEME_TERMINAL_VERSIONS`, which the adapter compares, and a tab whose palette's version moved — a new picture, a tone, a mode — takes its profile again at its next prompt or focus (`__tt_terminal_follow`, from `__tt_reloaded`); only a palette that gains its first picture while Terminal runs shows it after a restart, its profile in Terminal's memory having no bookmark. A tab wears an installed palette by taking its profile (`__tt_terminal_wear` → `terminal-app.js tab <tty> <profile> <fallback>`, run from Terminal's own tab, so macOS asks nothing): the script switches the tab to the palette's profile wherever Terminal holds one — answering `worn` where Terminal loaded it as it is now (its `TthemeAt` before `LastTerminalStartTime`) and `stale` where the palette's colors moved since (a tone, a mode), and then the adapter paints the palette's OSC colors over the profile's (`__tt_terminal_wear` answers 2) while the picture is already the new one, since `lay` rewrites the file the profile's bookmark resolves to in place — and only for a palette Terminal does not hold (added while it runs) moves a tab on a ttheme profile onto the user's own (`TTHEME_TERMINAL_APP_BASE`), so the OSC colors the adapter then paints are not hidden under a picture. A `stale` tab keeps its picture through a mode switch or a tone (parity's `mode`, `auto` and `tone-reach` pictures). `TTHEME_TERMINAL_SHOWN` (`<palette> <version>`, exported) names what the tab's profile shows, so a wear it already shows costs nothing, a new tab whose heard colors are the startup palette's starts from it, and the CLI hands it on (`__tt_cli_env`, with `TTHEME_TTY`). A one-shot `osascript` takes about 170 ms (a fork, paid by verbs, pins and a follow, never by a prompt that changes nothing); preview runs the script as a coprocess (`serve`, from `__tt_pv_bg_open`) and a hover switches profiles in 16–33 ms (measured), and a switch keeps the window's size. A profile switch drops every color an OSC set, so preview's tuning shows a tuned or other picture by laying it into the palette's file under a view name and taking the profile again (`__tt_terminal_view`, through `ttheme flatten … <into>`, run by `_bg.zsh`'s background runner as `__tt_terminal_lay`, which finds the palette's file when it runs, since each lay renames it, and whose completion, `__tt_bg_done`, takes the profile again and keeps the state as `TTHEME_TERMINAL_LAID`), and a picture back at its saved state, leaving or cancelling lays the saved one back (`ttheme image <palette> tuned`, behind the key loop too while preview is open, and `__tt_terminal_unview` when it closes); the strip draws empty frames (`__tt_bg_send` fails), find is not offered (`__tt_pv_bg_findable`), no post is a link (`TRAITS['terminal-app'].links`), and preview sends no kitty sequence, which Terminal prints as text (`__tt_bg_wipe`). Browse and init's picker keep a pictured tab's picture under the colors they show (`terminalLive`, `src/terminals/terminal-app-live.ts`, which `liveOf` tries before `livePaint`): once the cursor rests they lay the tab's picture on the hovered background into its palette's file, take the profile again and only then paint the hovered OSC colors, and leaving — closing, or the hub's switch back to Preview, which skips `restore` but runs `stop` — lays the file back under the name Terminal still holds. `point` writes `Default Window Settings` and `Startup Window Settings` through `defaults` and gives the user's own back while off or uninstalled (when it also drops every ttheme profile). Terminal reads its settings at launch, keeps every profile there in memory, and never sees a later write until it restarts — but keeps it (measured): so a profile written while it runs is loaded only at its next launch, which `point` reports as a needed restart (`loaded`: the profile's `TthemeAt` against Terminal's `LastTerminalStartTime`), while a running Terminal takes a new default from its own tabs: the terminal-app adapter's `__tt_reloaded`, whenever `palettes.zsh` moved, reads the default from the settings (`defaults read`, one process, only then) and, when it differs from the last one it told Terminal (`$XDG_STATE_HOME/ttheme/terminal-app.default`), sets Terminal's `default settings` and `startup settings` through AppleScript (`__tt_terminal_tell`, an `osascript` run from Terminal's own tab, which macOS lets through without asking, as an app scripting itself) — and only to a profile Terminal has loaded. AppleScript never writes a color: it would store it as calibrated RGB, which draws lighter, and drop the background's alpha (both measured). A new tab opens on the startup palette's profile, so it shows the palette and its picture whole and wears it from its first frame (its shell hears the 20 colors as before, and wears the palette again over a tab whose profile carries an older version of it — a tone changed while Terminal ran — only where the background already matches); a tab that never painted follows a new default by taking its profile (`__tt_takes_default`), and a reset takes the startup palette's profile while ttheme is on, and while it is off moves the tab onto the user's own profile, which drops every color an OSC set (measured) — or paints back what the tab heard at start where Terminal has not loaded that profile. In a setup init did not wire it in, Terminal.app stays unwired. The sandbox's `--terminal-app` wires it into the user's real settings, which `tests/terminal-prefs.zsh save` keeps first (once, in `$TMPDIR`, so a crashed run's leftovers never become the backup) and `restore` puts back when the run ends, removing every key the backup lacks; compat does the same.
