# site/

The design system is the Design System artifact https://claude.ai/artifact/D3TtwiZtWyM175ydwyWCyv: read its README before styling anything. `app/globals.css` is its code form. `site/AGENTS.md` has the build, docs and browser-support rules.

## Server, pages and cards

- `site/` is an Elysia 2 app (`elysia` pinned to `2.0.0-rc.0`: a bump is a deliberate step and Dependabot ignores it) that renders KitaJS JSX (`@kitajs/html`) to strings: no React, no client framework. `@elysia/html` is not used, since its `mapResponse` never reaches the outer app's 404 and 500. `server.ts` is Vercel's entry (`export default`; Vercel refuses `listen`) and `dev.ts` the local server; both `use(autoHead())` first, since Elysia 2 answers `HEAD` only through it.
- `app/site.tsx` holds the routes and the 404 and 500 handlers. `onError('global', …)` goes in the first calls of the chain, since a hook reaches only the routes added after it. A marketplace's routes and a share link's card and credits are `group`s whose `derive` looks the thing up once and answers a miss itself with `status(404, …)` (a page group with the HTML page, a card group with a line of text), never a thrown error class. A route that wants `FIXED`'s `cache-control` says `{ fixed: true }`. `/builder/:code` takes no schema: `readShared` reads a bad `?i=` as the first palette on purpose.
- Every response goes through `page()` (`app/document.tsx`): the document, its status, its `cache-control` and an `etag` hashed from its bytes. A route passes its `path` (a page with one carries `<link rel="canonical">` and `og:url` on the production origin, `SHARE_URL` in `src/core/own.ts`, never a preview URL), its `ld` graphs (`lib/seo.ts`: the landing's `WebSite` and `SoftwareSourceCode`, never `SoftwareApplication`) and its `robots` (`noindex` for a share link's page, which never gets a `Disallow: /builder/` in `robots.txt`, since a link preview's crawler obeys it too).
- Every page's title and description come from `lib/titles.ts`. Every page carries `og:type`, `og:site_name`, `og:locale` and a `twitter:card` (`summary_large_image` with a card, whose `og:image:type` and alt texts name the palette) and links `/apple-touch-icon.png`.
- Every page a visitor shares has a card (`lib/card.ts`): a palette page and a marketplace page their own at their path plus `/card.png`, a share link its code's, the landing and `/marketplace` the first lead's (`fallback`); the 404 and 500 pages have none. A route passes its card as a path, which `Document` puts on the production origin, and `og:image` carries `?v=` and `CARD_REV` (`lib/seo.ts`).
- A card is one SVG string that `raster()` (`lib/raster.ts`, `@resvg/resvg-wasm`) turns into a PNG, embedding its wasm and fonts through the macros in `lib/embed.ts` so the bundle reads no file. A font's family is read from its `name` table, never typed; a text is measured by rendering it (`ink`, `fit`); a character the fonts lack draws as nothing.
- `lib/tab-icon.ts` keeps the icons (`touchIconPng`, `faviconIco`) on the pure-TypeScript `encodeRgb`, and `site/lib/tab-icon.test.ts` holds that a rectangle with no corner is painted whole. `/robots.txt` allows every path and names `/sitemap.xml` (`sitemapXml`: a `loc` for every `PRERENDERED` path, no `lastmod`).

## Browsers and CSS

- The site works in every browser Baseline calls widely available (Chrome and Edge 124, Firefox 125, Safari 17.4): every page reads, every link and copy button works and every widget runs there. Anything newer is an enhancement whose fallback is named where it is described; relative colors sit behind `@supports` over a `color-mix()` fallback and a newer DOM API behind a check. `light-dark()` is the one exception (Safari 17.5): the slots are registered `<color>`s, which take no `light-dark()` in 17.4, so a palette that is not the page's shows in the page's colors there. Read a CSS feature's floor from `web-features`, not from Playwright's WebKit builds, which run newer.
- Tokens use shadcn's vocabulary plus `soft-foreground`, `faint-foreground`, `success`, `warning`, `overlay`, `glass`, `glass-panel`, `raised` (`raised-low`, `raised-edge`, `raised-shine`) and `star`. There is no second theme: `:root` wears a palette, and `globals.css` maps every token onto the slots `--bg`, `--fg`, `--cu`, `--se` and `--a0`–`--a15`. Shadows are the dark `--elevation-*` ones, softer under `:root[data-mode='light']`.
- Only the scale: text `2xs` 11 · `xs` 12 · `code` 12.5 · `sm` 13 · `base` 15 · `display-sm/md/lg` (fluid), `display-xl` for the landing's hero and `mega` for the landing footer's wordmark only; radius from `--radius: 10px` (sm 6 · md 8 · lg 10 · xl 14 · 2xl 18 · 3xl 22); spacing on Tailwind's 4px steps. Arbitrary values are for layout tracks, breakpoints and blur only. `cn` (`lib/utils.ts`) extends tailwind-merge with the custom text sizes: add any new `--text-*` there.
- UI parts live in `components/ui/*`: KitaJS components whose looks are `cva` variants in their own file, never a long `class` passed from a feature component. Every part renders `data-slot` (and `data-variant`, `data-size`) and carries no `dark:` variants. A `RadioGroup` is a radio group with no script, and a toggle that only picks which panel shows needs none either: a named `group` with `hidden` panels and a `group-has-[input[value=…]:checked]/<group>:` variant spelled out per value, since Tailwind generates only classes it finds whole in the source.
- Icons are `lucide` nodes drawn by `Icon` (`lib/icons.tsx`); a brand wears its own mark from `simple-icons` through `BrandIcon`, set before the brand's name. A link off the site opens in a new tab (`target="_blank" rel="noopener"`, without `noreferrer`) and ends in `NewTab`, except the header's star button and a marketplace card's repository and `updated` buttons; in the footer `NewTab` goes inside the label's `span` (`OutLabel`), the label's last word and the arrow in one `whitespace-nowrap` span.
- Faces: `font-sans` Inter for UI; `font-display` `Nunito` → `Hiragino Maru Gothic ProN` → `BIZ UDGothic` for palette names and page titles at `font-black` (list rows `font-extrabold`); `font-mono` JetBrains Mono for commands, ids, hex values and terminals. Every face goes through `subset()` in `build.ts`, which keeps only the layout features a browser turns on by itself (`SHAPING`) and the ones the site turns on (`FEATURES`: `body`'s `cv02 cv03 cv04 cv11 ss01`, which the mono text inherits too, and `tnum`): a stylesheet that turns on another feature adds it there. The mono subsets (`MONO_SUBSETS`) cover every code point between them with no catch-all face. Fonts go to `public/assets` under a content hash, woff2 only and never inlined into the CSS; only the latin Inter, Nunito 900 and the regular JetBrains Mono `core` are preloaded.
- Names and commands carry `translate="no"` on the element that holds the name, never on a section that also holds prose. A work's native title carries its language wherever it shows (`langOf`, `lib/theme-entry.ts`): `ja` for kana, `ko` for Hangul, `ja` for Han alone only for a work the commons holds; a Latin title carries none.
- Printed, a page wears no palette: `@media print` sets `--bg`, `--fg`, `--cu` and `--se` to ink on white (`!important`), `color-scheme: light` and `print-color-adjust: exact`, and drops the facet ground, the route progress bar, the kaomoji rain and the cycle's line.
- Forced colors drop every `box-shadow` and paint author backgrounds `Canvas`: `globals.css` draws focus there as a 2px `Highlight` outline (on the focused element, or on the label around a visually hidden radio) and paints the glide underline and the progress line `Highlight`. A swatch (`Signature`, `Swatch`, the ANSI pills, `signature-dots`, `work-tile`, `work-swatch`, `palette-dots`) takes `forced-color-adjust: none`; nothing that holds text does. `prefers-contrast: more` lifts the muted foregrounds and borders and `prefers-reduced-transparency` makes the glass opaque.
- Every page has one `<main id="content">`, and `Document` puts a `skip to content` link to it first in `<body>` (`not-focus:sr-only`). `html`'s `scroll-padding-top` is 64px, and the header's own links, buttons and radios move their scroll target down by `--clearance` (`scroll-margin-block`) outside an open popover.
- A page wrapper that is a `grid` needs `grid-cols-[minmax(0,1fr)]` (a `<button>` used as a grid container too), or a child's min-content widens the track past a phone's width.
- Every swatch that stands for a palette is one element (`signature-dots`, `work-tile`, `work-swatch`, `palette-dots`); never draw one with an element per color. Never put `content-visibility: auto` on rows, tiles or any list a visitor jumps through.

## Client code

- Interactivity is vanilla TypeScript in `client/`, bundled by `Bun.build` into one module. Each page's widget is a custom element (declared for JSX in `custom-elements.d.ts`) reading its data from a `<script type="application/json">` the server wrote with `json()` (`lib/render.ts`, which escapes `<`, `>` and `&`). `palette-builder` is a second entry point built without splitting (`assets.json`'s `builder`), loaded only by `/builder` (`page()`'s `module`).
- A list of palettes is fetched, never inlined: `marketplace-workspace` fetches it once the page has painted (`afterPaint`) or at the first move that needs it (`palettes()` in `client/palettes.ts`, `priority: 'low'`, forgotten when it fails) from `palettesPath` (`lib/gallery.ts`), files `build.ts` writes beside the pages (`DATA`). A widget never waits on that list to show what the page drew: until it arrives a palette link is followed as a link, and a step, arrow, tab or tile waits and then acts (`#when`). A widget re-renders a changed fragment with the same KitaJS component the server used (`html()`, then `fill` or `swap` from `client/dom.ts`).
- Every command a page offers to copy is a `CommandRow` (`components/command-row.tsx`), the docs' one-command `sh` fences included: the command colored by `highlightHtml`, an end that fades once it overflows, and a ghost copy button at its end. `RunnerRow`, its form with a command per runner (`InitRow`, a docs `npx`/`bunx` tab pair), puts a strip of runner tabs over the line, each the runner's npm or Bun mark and its name (a `ToggleGroup`), and draws both commands, each with its copy button; `<html data-runner>` shows one, set before the first paint by `RUNNER_SCRIPT` (`lib/runner.ts`, `RUNNER_KEY` in `localStorage`) and moved through `client/runner.ts`, so every row on every page follows one pick; a card's command stays npx.
- A copy button is any `[data-copy]` button handled by one delegated listener (`client/copy.ts`): it says `copied` through the page's one polite live region (`[data-announce]`, written by `announce()`), and when the clipboard refuses it selects the shown text and says to press ⌘c or ctrl+c. Its `data-copy-status`, or that hint, shows for its hold in the page's one tip (`client/tip.ts`, `flash()`): an `aria-hidden` `popover="manual"` in the top layer, so no header, dialog or clipping box covers it, above the button or under it at the window's top, hidden by Escape, a scroll or a resize. Nothing else shows a tip: a hover or a focus shows none. A filter that narrows a list says how many it left through `tally()`, half a second after the last keystroke.
- A page's keyboard shortcuts go through `client/keys.ts`. A single key never fires with ⌘, ctrl or alt held, for a key the page already handled (`defaultPrevented`), in a field (`typing`) or during an IME composition (`composing`); ←/→ in a palette's workspace also never with shift, in a tablist or a popover or for a held key's repeats. The one chord, ⌘K or ctrl K on `/marketplace`, focuses the search; its `Kbd` shows `⌘ k` or `ctrl k` from the first paint through `KEYS_SCRIPT` (`lib/keys.ts`, which marks `<html>` `data-apple`). A search field is `autocapitalize="none"` and `autocorrect="off"`.
- `Dialog`, `Popover`, `Tabs`, `Collapsible`, `Combobox`, `Toggle` and `ToggleGroup` are Base UI's parts on native elements: their script in `client/ui/` (imported by `main.ts` alone, since `palette-builder` is a bundle of its own) finds them by `data-slot` and does the opening, placing, focus and keys; a feature only composes them. `DialogTrigger` (`commandfor`) opens the `<dialog>` with `showModal()`, `DialogClose` is a `<form method="dialog">`; a `Popover` with an `align` sits under the `PopoverTrigger` that opened it; a `TabsTrigger` shows its `TabsPanel` (`aria-controls`); a `Collapsible` is a `<details>` whose panel the script grows and shrinks, while `open` set from code changes it at once; a `Combobox` filters its items by `data-text`, says the count (`tally()`), moves `data-highlighted` with ↑/↓ and picks with Enter or a click, never during an IME composition; a `ToggleGroup` keeps one `Toggle` pressed. A change is told before it happens, in Base UI's names: `openchange`, `valuechange` or `pressedchange`, with `reason` (`none` for one set from code) and `trigger`, cancelable but for a popover closing (a light dismiss cannot wait). State the script owns is Base UI's attribute (`data-open`, `data-closed`, `data-starting-style`, `data-ending-style`, `data-popup-open`, `data-active`, `data-highlighted`, `data-selected`, `data-pressed`), which the motion in `globals.css` keys on; state the browser owns stays its own (`:checked`, `:popover-open`); a feature that owns a toggle's state sets it through `client/ui/pressed.ts`, which the builder may import. A trigger, `DialogClose`, popup or `Toggle` takes `render`, drawing its element from the part's attributes; `Collapsible`, `Combobox`, `Toggle` and `ToggleGroup` have no look of their own. A popover closes when focus leaves it for anything but its trigger, and on a resize that leaves no trigger of it rendered.
- Client code never imports `lib/builtin.ts`, `lib/marketplaces.ts` or `lib/share.ts` (a type-only import still pulls a module into the program), and of the root's `src/` only `src/core`'s modules that do no I/O (`draft.ts`, `sets.ts`, `tune.ts`, `slots.ts`, `contrast.ts`, `plane.ts`, `mirror.ts`, `mark.ts`, `scaffold.ts`, `zip.ts`, `builder-layout.ts` and what they import), never `own.ts`, `png.ts`, `jpeg.ts` or `tarball.ts`. Shared code (`components/`, `lib/`) touches neither `document` nor `Bun`.

## The worn palette

- `<html>` wears the site palette on every page: `Document` writes the first lead (`fallback`, `lib/builtin.ts`) and `WEAR_SCRIPT` (`lib/wear.ts`), inline in the head, overrides it before first paint with the visitor's stored pick in the mode the visitor chose. `wearVars(theme)` is the raw slots (`wearSlots`) plus `--wear-name` and `--sg0`–`--sg2`, the palette's cursor, selection and foreground (`faceOf`, `FACE`); `rootStyle` writes them on `<html>` and `show()` (`client/wear.ts`) on the client. A palette's address shows that palette in the workspace's preview pane only. A window that shows another palette (the palette page's preview, a marketplace card's, the landing's tab window, the pins player, the builder's mock) sets the slots on its own `TerminalFrame` only.
- `<html>` carries `data-mode` (the mode worn) and `data-setting` (`auto`, `dark` or `light`; `lib/mode.ts`, `MODE_KEY` in `localStorage`), and its `color-scheme` is `light only` or `dark only`. Every `Theme` carries both modes (`toTheme` in `lib/theme-entry.ts`, server only, from `inMode` in `src/core/manifest.ts`). A color of a palette other than the page's is written as `light-dark(<light>,<dark>)` (`paint`, `pair`); a text or contrast that depends on the mode is drawn once for each mode inside `ByMode` (`components/by-mode.tsx`) and `globals.css` hides the one that is not worn. A share link opens on the mode its palette was made in; only `EditMode` moves it.
- A text that names the palette a page shows is drawn from the page's own vars, never written into the markup, wherever a stored pick can change it before the module runs: an empty `<span data-text="name">` (or `work`) gets its text from `globals.css` (`[data-text='…']::after { content: var(--…) }`), the string being JSON in its var. `<html>` also carries `--palette-name`, `--palette-work` and `--palette-em` (`wearOwn`), which the hand-off never carries.
- The mark `>ω` has one source for every drawing of it, the CLI's too (`src/core/mark.ts`). `--mark0`–`--mark2` are derived from `--cu`, `--se` and `--fg`, never stored (`marksOf`, `withMarks`; `WEAR_SCRIPT` computes them with its own copy of the lift, `LIFT`; `worn()` carries them through a hand-off). The word `ttheme` is a drawing, not text (`lib/wordmark.ts`, `WORDMARK`; `Wordmark`, `wordmarkSvg`). The tab icon wears the palette too (`wearIcon`, `lib/wear.ts`): the server writes the page's, `WEAR_SCRIPT` the stored pick's from the same `tileSvg` template. Regenerate the Nunito advances (`headlineEm`) whenever the Nunito package changes.
- The site palette is picked in the header's `palette-picker` (`client/palette-picker.tsx`): it lists the built-in palettes from `/marketplace/ttheme/palettes.json`, and `choose()` (`client/wear.ts`) stores the pick in `localStorage` (`WEAR_KEY`: `{ v: { dark, light }, t }`), dispatches `ttheme:wear` and, unless a listener took it, shows it on `<html>`. Its list is a `Combobox` in a `Popover`, so focus never leaves the search.
- A page arrives in the colors the page before it showed and fades into its own. At `navigate`, `client/handoff.ts` writes the old page's colors to `sessionStorage` under `HANDOFF_KEY`, and `HANDOFF_SCRIPT` (`lib/handoff.ts`, inline in every head after `WEAR_SCRIPT`) takes them at `pagereveal` when the record names this URL; `arrive()` (`client/wear.ts`) redraws the facet ground in the old colors and fades to the page's own. Every page opts into cross-document view transitions (`@view-transition { navigation: auto }`) and captures nothing (`:root` keeps `view-transition-name: none`); the leaving page skips the transition at `pageswap` (`swap()`) unless it is a back or forward move to an entry whose colors differ. Under reduced motion nothing is handed off.

## Motion

- `show()` fades `<html>`'s slots and the face colors (`TONES`) over 0.4s (`FADE`, `client/wear.ts`) by writing each frame's mix itself, a `requestAnimationFrame` loop timed by a target-less `Animation`, and holds `data-settling` on `<html>` from the fade's start to the frame after its last, which turns off every descendant's own transition. Never fade the slots with a CSS transition or animation: Chromium taints an animated custom property, and a visited link then draws its parent's text color.
- The change itself runs inside `fadeThrough()` (`client/dom.ts`, one `document.startViewTransition`): a fragment whose text the palette changes carries a `view-transition-name` only while it runs (`:root[data-fading]`, scoped in `globals.css`), and nothing else is captured (`:root` takes `view-transition-name: none`, `::view-transition` `pointer-events: none`). `fadeThrough` clips the transition layer to the band between the `[data-sticky]` bars through a stylesheet of its own adopted by the document, never through a custom property on `<html>`.
- A palette change restyles every element on the page, so nothing that runs as one starts reads layout after writing: `getBoundingClientRect`, `innerHeight` and `scrollBy` each force that pass again. Read first, write after, and scroll in the next frame. A selector that an attribute set on `<html>` during a change reaches ends in a compound with an attribute, class, id or tag of its own.
- The facet ground (`components/facet-ground.tsx`, `client/facet-ground.ts`, `lib/facets.ts`) is on every page: a fixed field of low-poly triangles whose every color comes from one function, `shade`. The server writes it as SVG with each facet's `--tint` and `--lift` for the resting lamp (`FACET_LAMP`), then `client/facet-ground.ts` draws the same field on a canvas with the same function and OKLab math and takes the SVG out of the DOM: never move per-facet work back into DOM elements or CSS, since the palette fade restyles the document each frame. `SHOW_EVENT` only records the wave; where it starts is measured in the next animation frame (`#turn`, from `#step`). The field knows a palette by the colors it draws with, never by its name, and is drawn still under reduced motion.
- The route progress bar (`route-progress`, `client/route-progress.ts`, `lib/route-progress.ts`) is first in `<body>` on every page: a `role="progressbar"` labelled `loading`, `visibility: hidden` while idle, following the Navigation API's `navigate` event for navigations to a page of this origin. It moves only `opacity` and `translate`, which the compositor runs, and JS only sets `data-state`: never drive it through a custom property animation. At `navigate` the old page writes `{ at, nav }` to `sessionStorage` under `ROUTE_KEY` at the start, never at `pagehide`; `ROUTE_SCRIPT` takes it only when `Date.now() - nav` is within 500ms of `performance.now()`.
- A terminal's cursor (`[data-c]`) blinks a cover in the terminal's own background (`::after`, `z-index: -1` under an `isolation: isolate` cell) by `opacity`, never the cell's `background-color`; a redraw restarts it, so a cursor that is typing holds still.
- The head's inline scripts (`KEYS_SCRIPT`, `RUNNER_SCRIPT`, `WEAR_SCRIPT`, `HANDOFF_SCRIPT`, `ROUTE_SCRIPT`) are classic scripts sharing one global scope: keep a script's working variables inside its functions. A value the server writes into one goes through `json()`, never a bare `JSON.stringify`.
- `SPECULATION_RULES` (`lib/speculation.ts`) is in every head (`moderate`, with the marketplace workspace's palette links, `[data-pick]`, left out). A prerendered page runs its head when the prerender starts, so `remember()` and a `storage` event for `WEAR_KEY` call `respeculate()` (`client/speculation.ts`): a task later it removes the rules script and a task after that inserts a fresh one, never in the task that picked the palette. Chrome turns prerendering off for a page DevTools is attached to.

## Header, footer and layout

- One header and one footer for every page but the marketplace workspace and `/builder`, which keep the header fixed (`data-fixed`) and close on their own status bar (`AppBar`). `SiteHeader` (`components/site-header.tsx`) spans the window with its row on the page's 1280px track: the wordmark and `marketplace`, `builder` and `docs` links, the header bar (`HeaderBar`: the palette picker's pill and the mode switch's round button) and `github` as a star button on the right. A page puts the header outside its track wrapper, first in its `ground` element, and the footer last in it. `Facts` (`lib/facts.ts`) is built once in `app/site.tsx` and passed down as a prop, since `components/` cannot import `lib/builtin.ts`.
- Every width the header answers to is its row's own: the row is a size container (`container: site-header / inline-size`), and the custom variants beside `app` in `globals.css` are the one place those widths are written (`header-wide` and `header-menu` from and below 720px of row, `header-short` 720 to 792px, `header-tight` below 680px, `header-icons` below 440px). A part added to the row, or a label that grows, moves them: re-measure the full row's need (plus 12px, rounded up to 8) at every width. No part that cannot shrink gets `min-w-0` (a group with it paints past the group over its neighbor); a part that can give way truncates. The row, the left group and the nav wrap (`flex-wrap`, the header's `min-height`). Tailwind's `max-[Npx]` is exclusive and `min-[Npx]` inclusive, so a pair takes the same N.
- The header folds with the scroll without ever moving the page (`[data-site-header]` in `globals.css`): it is 52px plus `--fold` (32px, 16px below a 720px window) tall and sticks at `top: calc(var(--fold) * -1)`, and scroll-driven animations (`scroll(root)`) fade in the glass and hairline (its `::before`, opacity only), move the row onto the 52px the sticky header leaves and take the wordmark from `display-md` to `display-sm`. The unfolded header is the resting style and the fold is what the animations add, since a page with nothing to scroll has an inactive timeline, which draws no animation. Without scroll-driven animations `--fold` is 0.
- The header arrives as the page before it left it. The `navigate` record also carries `f` (how far the header was folded) and `g` (the header link the underline sat under); `HANDOFF_SCRIPT` sets `data-unfold` and `--unfold` on `<html>` before the first frame, and CSS animations with only a `from` keyframe (`header-unfold`, `glass-unfold`, `row-unfold`, `wordmark-unfold`), each listed after its scroll-driven one, start where the old page's scroll left them; the script drops both on the header's own `animationend`. They are CSS, not script, because Chrome runs several animation frames before a new document's first paint. A fixed header counts as folded, and a move between the two kinds of header slides each side (`row-shift`). A traverse is not handed off.
- The header's nav and each footer link column are a focus group, `[data-glide]` in `globals.css`, with one 2px underline (the group's own `::before`) that CSS anchor positioning lays 1px under one link's label and no script touches: the link holding keyboard focus, else the one the pointer is on, else the current page's (`aria-current`). Every link wraps its label in a `<span>`, and that span alone carries `anchor-name: --glide`. The group rests on its current page; a group with none unfolds the underline from its middle and folds it back, a delayed discrete transition keeping the span's `anchor-name` for that fold. While a link has the underline its siblings recede to `muted-foreground` and the links' own `decoration-primary` mark is turned off. Hover counts only where the pointer can hover; like every transition it stops while `data-settling` holds a palette fade. Without anchor positioning every link marks the current page with `decoration-primary`.
- The `app` variant (`@custom-variant app` in `globals.css`: 900px wide and 600px tall or more) is a layout that fills the window and never scrolls it; below either it is an ordinary page that scrolls. The marketplace workspace and `/builder` share `components/workspace-shell.tsx` (`WorkspacePage`, `WorkspaceSide`, `WorkspaceBar`, `WorkspaceTitle`, `WorkspaceStage`, `GateButton`; `.workspace` in `globals.css` is its grid). The bar and the stage share one inset (`INSET`); in the `app` layout the bar's 48px line lies where the sidebar card's 48px head lies, 12px under the header.
- Every terminal window the site draws follows Ghostty's macOS window through `TerminalFrame` (`components/terminal-frame.tsx`; the builder's is `MockWindow`): 14px corners (`rounded-xl`), a `ring-border` hairline, a title bar in the terminal's own background with no line under it, 12px lights 8px apart, and tabs in a rounded track (`rounded-lg`) whose selected tab is a lighter `rounded-md` block. Corners nest (14px, 10px, 8px) and share a center: keep them so. The builder's window wears the draft (its title bar the draft's background, its lights `--a1`, `--a3`, `--a2`), where the palette editor's mock in the terminal keeps fixed macOS lights.
- A terminal's text is `TerminalScreen` (`components/terminal.tsx`) over the runs of `lib/terminal.ts`, written in the scene markup of `src/core/scenes.ts` (`linesOf`) unless outside text goes in: a run names its text and ground slots (`data-t`, `data-g`, the numbers of `slotsOfRole`), bold (`data-b`), faint (`data-f`, 55% foreground unless the window sets `--faint`), the cursor (`data-c`), a live name (`data-live`, `data-text`) or another palette's color (`ink`, `ground`). One stylesheet colors every terminal (`[data-slot='terminal-screen']`): never color a run with a class or an inline style. A screen is one `<pre>` at `--term-leading` (1.5, the most under which JetBrains Mono's box drawing still joins), ligatures off; a grapheme outside printable ASCII sits in a box of its cells (`data-cells`, a wide one alone and centered), so a glyph the font lacks never shifts the columns after it, and a block element stretches to fill the line (`data-fill`). `cols` sizes the font to the nearest container (`data-fit`, 8px to `--fit-max`), as the landing's hero and a docs `screen` do. The workspace's `all` view lays its four screens out as splits through the `split:` variant.

## Pages

- Routes: `/` the landing (`components/home.tsx`), `/marketplace`, `/marketplace/<marketplace>` (`ttheme` or `owner@name`, `marketplacePath`), `/marketplace/<marketplace>/<palette>` (`palettePath`), `/builder` and `/builder/<code>` (the same page opened on a share link) and `/docs`. A page the deployment fixes is prerendered by `build.ts` into `static/` (`PRERENDERED`, `app/site.tsx`); an unknown marketplace or palette answers 404.
- The landing is the one page allowed a louder layer (the `pop` Button, `sparkle-burst`, `animate-dance`, color emoji, `kaomoji-rain`); every other page stays soft: cards and the dialog `rounded-3xl`, buttons `rounded-full`, inputs and command rows `rounded-lg`, `ease-spring` only on a card's `animate-enter` and press, a kaomoji only in a passing state, one per view, never in a heading, doc or error, always `aria-hidden`.
- The landing's hero never moves under its visitor: its name, the preview window's title and the name in the preview's `ttheme use` line are drawn from the page's vars (`[data-lead-name]::after`, `data-text`, `OWN_NAME`). The headline is always two lines: the name's `font-size` is `min(1em, (100cqi − prefix) / --palette-em × 0.97)`, with `--palette-em` from `headlineEm` (`lib/wear.ts`) and `--lead-prefix` for `wear `. The cycle of leads pauses while the hero is less than a quarter in view, while the pointer is over the preview window and while the tab is hidden, stops when the visitor picks a palette or keyboard focus enters the hero until they start it on the rotation control (`[data-lead-rotate]`), starts stopped with a pick stored (`<html data-picked>`), and does not exist under reduced motion. A key held down on the previous and next buttons acts once. The preview window's terminal is `aria-hidden`.
- The landing's `HeroScenes` (`components/cli-scenes.tsx`) draws the CLI's own scenes (`src/core/scenes.ts`, and the palette editor's `paneLines` in `src/core/builder-layout.ts`) at 83 columns and 24 rows, computed inside the render so the browser bundle holds none of them, and `PerTab` (`components/tab-window.tsx`) a tab's session (`tabLines`, `lib/sessions.ts`). `TerminalList` lists the terminals `init` wires, each an app icon (`app/terminals/`, shipped through the `Shelf` as `assets.json`'s `terminals`) linking to the terminal's own site.

A button that looks pressable always goes somewhere; the list shows no gate.

A marketplace's own page names it in a visually hidden `h1`. The workspace's window has a mode switch of its own (`WindowMode`), synced with the page until used; a dirty window (`data-window-mode` on `<main data-mode-scope>`) is never stored and is clean again on any new page load. The builder's mock has `EditMode` instead.

## Deployment

- Vercel follows `vercel.json` (`framework: null`, Bun `1.x`, the project's Root Directory `site`): the theme build, then `build.ts`, which writes the assets to `public/assets` and then the Build Output API directory `.vercel/output` that Vercel deploys as it stands (`output()`): `static/assets` content-hashed and `immutable` through a route header, every response carrying `SECURITY_HEADERS` (no CSP, whose policy the document's inline scripts would need nonces or hashes for), the prerendered pages as `static/<path>.html` served at `<path>` through `config.json`'s `overrides`, and one Bun function `functions/render.func`, the server bundled whole with no `node_modules`, which every path the filesystem misses is routed to. It is not named `index.func`, which took `/` from `index.html`. Vercel's Elysia preset is not used.
- Only `main` deploys: `vercel.json`'s `git.deploymentEnabled` builds no preview for another branch or a pull request.
- The function's `.vc-config.json` (`output()`) copies what Vercel's own Elysia preset writes for a Bun function (`runtime: bun1.x`, `launcherType: Nodejs`; `architecture` left out). Before changing a field, compare it with what the preset writes now: `vercel build` on a copy without `framework: null` whose entry, named by `outputDirectory`, imports `elysia`.
- `dev.ts` serves `/assets/*` itself with `no-store`, but for the fonts, which `Shelf` names by their content in dev too and `dev.ts` answers `immutable` as the CDN does. GitHub Pages keeps the README's pictures, the marketplace index and `stars.json` (`mise run pages`), and `pages.yml` deploys them, on a push or on its schedule, only when one of the files differs from the published copy; a run started by hand always deploys.

## Traps

- Lightning CSS, which Tailwind runs on the production stylesheet alone (`optimize: production` in `build.ts`), writes an `animation` shorthand that names no keyframes as `animation: none`. A rule that leaves the name to another rule takes its longhands (`animation-timing-function`, `animation-fill-mode`), and `site/app/globals.test.ts` fails on any scroll-driven rule the optimized stylesheet turns into `animation: none`. Check CSS on a built site, not only the dev server.
- KitaJS escapes attributes but not children: a string child takes `safe` on its element, or `escapeHtml()` as a component's child, and `xss-scan` (`@kitajs/ts-html-plugin`, run by `site:build`) fails otherwise. Both KitaJS packages are pinned to their 5.0 prereleases, which need TypeScript 6, so `site/` stays on 6 and Dependabot skips TypeScript's majors there. An `aria-*` that must read `false` is written `String(value)`. `xss-scan` takes `.map()` over an array from a JSON import for unescaped content: give the array a typed constant first (`FONTS` in `app/document.tsx`).
- Two TypeScript programs: `tsconfig.json` (the server and the shared code: `esnext` and Bun's types, no DOM) and `client/tsconfig.json` (the DOM, no Bun, and only the built-ins of the oldest browsers the site supports: `es2023` and ES2024's `collection`, `object`, `promise`, `regexp` and `string`, so an iterator helper, a Set method, `Promise.try` or a resizable `ArrayBuffer` fails `site:check` in client code and in every `src/core` module it reaches). `Bun.build` lowers no built-in. `booru.ts` reads its settings through `typeof process`, which `client/runtime.d.ts` declares as possibly undefined for the browser program.
- The dev server's reload stream (`/__reload`, `RELOAD` in `app/document.tsx`) holds an HTTP/1.1 connection and Chrome opens at most six per host, so a page holds its stream only while it is visible or prerendering. The server sends its build stamp (`stamp` in `dev.ts`) when a stream opens and after each rebuild, and a page reloads when a stamp differs from the first it heard. The stream is an `async function*` route that yields `sse()` and sends a named `event: ping` every 5s, since Bun closes a connection idle for 10s.
- `site:dev` and `site:build` both write `site/public` and `site/assets.json`, and the dev server restarts when `assets.json` changes: stop it before a build.
