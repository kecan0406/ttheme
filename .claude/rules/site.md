# site/

## Conventions

- The design system is the Design System artifact https://claude.ai/artifact/D3TtwiZtWyM175ydwyWCyv — read its README before styling anything. `app/globals.css` is its code form.
- `site/` is an Elysia 2 app (`elysia` pinned to `2.0.0-beta.26` — a beta, so a bump is a deliberate step) that renders KitaJS JSX (`@kitajs/html`, the `jsxImportSource` in `tsconfig.json`) to strings: there is no React and no client framework. `app/site.tsx` holds the routes and the 404 and 500 handlers (`error('global', …)`, so they also answer paths no route matched), and every response goes through `page()` (`app/document.tsx`: the document, its status, its `cache-control` and an `etag` hashed from its bytes, which Vercel's CDN answers a browser's revalidation with as 304, a cache miss included) — `@elysia/html` is not used because its `mapResponse` is plugin-scoped and never reaches the outer app's 404 and 500. `server.ts` is Vercel's entry (`export default`; Vercel refuses `listen`), `dev.ts` the local server; both `use(autoHead())` (`elysia/auto-head`) first, since Elysia 2 answers `HEAD` only through it, and without it every page and the `og:image` answered a link preview's or a monitor's `HEAD` with 404.
- UI parts live in `components/ui/*`: KitaJS components whose looks are `cva` variants in their own file, never a long `class` passed from a feature component. Every part renders `data-slot` (and `data-variant`/`data-size`) and carries no `dark:` variants — tokens do the theming. Behavior comes from native elements, not a library: `Dialog` is a `<dialog>` opened with `showModal()` (focus trap, Esc, `::backdrop`; `:root:has(dialog:modal)` locks the page's scroll), a `ToggleGroup` is a radio group (`has-checked:` styles, arrow keys for free), `TabsList` a `role="tablist"` whose keys `client/tabs.ts` moves, `ScrollArea` a native overflow box. Icons are `lucide` nodes drawn by `Icon` (`lib/icons.tsx`).
- Interactivity is vanilla TypeScript in `client/`, bundled by `Bun.build` into one module: each page's widget is a custom element (`lead-showcase`, `sheet-browser`, `share-sheet`, `palette-gallery`, `theme-toggle`, `sparkle-burst`, `kaomoji-rain`; declared for JSX in `custom-elements.d.ts`) that reads its data from a `<script type="application/json">` the server wrote with `json()` (`lib/render.ts`, which escapes `<`, `>` and `&`), and re-renders a changed fragment with the same KitaJS component the server used (`html()`, then `fill`/`swap` from `client/dom.ts`), so every piece of markup has one implementation. A copy button is any `[data-copy]` button, handled by one delegated listener (`client/copy.ts`).
- KitaJS escapes attributes but not children: a string child takes `safe` on its element, or `escapeHtml()` when it is a component's child, and `xss-scan` (`@kitajs/ts-html-plugin`, run by `site:build`) fails otherwise — market data comes from anyone's repository. Both KitaJS packages are pinned to their 5.0 prereleases, since 4.x's `xss-scan` exited 0 when it crashed and `site:build` passed unscanned; 5.0 needs TypeScript 6, so `site/` stays on 6 and Dependabot skips TypeScript's majors there until the plugin reads 7's API. An `aria-*` that must read `false` is written `String(value)`, since KitaJS drops a `false` attribute.
- Tokens use shadcn's vocabulary plus `soft-foreground`, `faint-foreground`, `success`, `warning`, `overlay`, `glass`, `glass-panel`: `:root` is light, `.dark` is dark, and `<html>` gets `.dark` from `THEME_SCRIPT` (`lib/theme-mode.ts`), inline in the document's head (a stored choice from `ThemeToggle`, else `prefers-color-scheme`). Shadows go through `--elevation-*` so each theme has its own.
- Only the scale: text `2xs` 11 · `xs` 12 · `code` 12.5 · `sm` 13 · `base` 15 · `display-sm/md/lg` (fluid) and `display-xl` for the landing's hero only, radius from `--radius: 10px` (sm 6 · md 8 · lg 10 · xl 14 · 2xl 18 · 3xl 22), spacing on Tailwind's 4px steps. `text-[13.5px]`, `gap-[9px]`, `rounded-[3px]` are off the system; arbitrary values are for layout tracks, breakpoints and blur only.
- Faces: `font-sans` Inter for UI, `font-display` `Nunito` → `Hiragino Maru Gothic ProN` → `BIZ UDGothic` for palette names, the wordmark and page titles at `font-black` (list rows `font-extrabold`), `font-mono` JetBrains Mono for commands, ids, hex values and terminals. Inter, Nunito and BIZ UDGothic come from Fontsource and JetBrains Mono from `app/fonts`, which `build.ts` cuts with `subset-font` into `unicode-range` blocks (`MONO_SUBSETS`: `core` — latin and the dingbats every mock terminal draws, ❯ ✓ ✗ ➜ —, arrows, math, technical, shapes, and `rest` for everything else), so a page downloads only the blocks its text uses — 72–80 KB of mono on each page instead of the whole 187 KB. Every font goes to `public/assets` under a content hash (woff2 only, never inlined into the CSS), its `@font-face` minified with the rest of the stylesheet, and only the latin Inter, Nunito 900 and the regular JetBrains Mono `core` are preloaded (preloading the bold `core` too moved LCP later on `/market` and `/p/<code>`). BIZ UDGothic is the display stack's last fallback, reached only by Japanese and a few symbols (the kaomoji, ✦), and its 248 faces were two thirds of the stylesheet, so they live in their own `cjk` stylesheet that loads without blocking render (`media="print"` until it loads). Each face has a `* Fallback` face in `globals.css` carrying next/font's metric overrides, so nothing shifts when it loads.
- Every page but the landing stays at this soft level and nothing louder: cards and the dialog `rounded-3xl` (22px), buttons `rounded-full`, inputs and command rows `rounded-lg`; neutrals carry a little of `primary`; `ease-spring` (a `linear()` spring with a `cubic-bezier` fallback) only on a card's `animate-enter` and press, never on hover; nav, labels and toggles lowercase; a kaomoji only in a passing state (`copied (・ω・)`, an empty result, no such market), one per view, never in a heading, doc or error.
- Routes: `/` the landing (`components/home.tsx`), `/sheets` a palette browser (`components/sheets.tsx`: the page wears the palette, a centered name with prev/next and ←/→, the tabbed TerminalWindow, a `ttheme use` row, a collapsible "slots and contrast" glass panel reusing the dialog's parts, and a sticky glass filmstrip of every palette grouped by series that keeps the current one centered; there is no picture/backdrop view any more), `/market` and `/market/<owner@name>` (`marketPath`), and `/p/<code>`, the page a share link opens (`components/share-page.tsx`: the palette read from the code in the address by the CLI's own `readCode` — nothing is stored —, laid out as a builder on the site's own tokens and never worn: a sidebar of the slots — the four base rows, the ANSI colors as normal/bright pairs, the gate with the slots a missed rule names — and the about tab, beside the palette editor's own mock window, whose `zsh`, `nvim` and `htop` tabs `paneLines` draws at a fixed grid (`GRID`, 120×34) that the window scales between 13px and 11px and crops below that, zsh keeping its last lines and the others their footers (`footerRows`); every run carries its text and ground slots (`data-t`, `data-g`). `share-sheet` adds the inspector (a run's slots and contrast on hover or tap, pinned by a click), the slot popover — the editor's plane and hue track (`reach`, `shareOf`, `RAINBOW_L`/`RAINBOW_C`), its value formats (`colorText`), `slotChecks`, `slotUse`, the run counts per tab and "show where it's used", which dims every run that draws with neither slot — and the add popover with the `ttheme add` and `init` rows; the pictures show as links to their posts, never the pictures themselves. `lib/share.ts` computes all of it on the server with the CLI's own functions and hands the browser a `ShareView` (`lib/share-view.ts`)), with `/p/<code>/card.png` as its `og:image` (`lib/card.ts`: the signature, a few bars of code and the sixteen ANSI colors, drawn with `encodeRgb`, no text); a code that does not read answers 404 with the reason. The landing is the one page allowed a louder layer on top, and only there: the `pop` Button (a 4px lip, one per page), the `sticker` Badge, `sparkle-burst` on the hero name, the dancing ANSI pills (`animate-dance`), `animate-squish` when the hero changes palette, color emoji on the feature cards, and `kaomoji-rain` (type `uwu`). It cycles the series leads every 4s until a visitor picks one, never under reduced motion, and hides the theme toggle since the page wears the palette.
- `.wear` makes an element wear a palette: `wearStyle(theme)` (`lib/wear.ts`) writes the raw slots (`--bg`, `--fg`, `--cu`, `--se`, `--a0`–`--a15`) as a style, `wear()` (`client/dom.ts`) sets the same slots on the client, and the class remaps every token onto them. The landing, `/sheets` and `PaletteDialog` wear the current palette whole; cards, `TerminalPreview` and the mock window of `/p/<code>` set the slots only. The market chrome stays on the neutral tokens.
- `/market` (`components/market-page.tsx`, `components/market-gallery.tsx`) lists the official series, then a `── Markets` line and each market, the CLI's order (`arrange`, `lib/gallery.ts`, places the headings, totals and the line for the server and again for the filters); a palette opens in `PaletteDialog` at `#<id>`. `/market/<owner@name>` (`components/market-store.tsx`) is one market's page, rendered on the server; an unknown one answers 404. Markets are read when a request needs them: `lib/markets.ts` calls `showcase()` (`src/showcase.ts`: GitHub's topic search for `ttheme-market` and each hit's archive, read by the CLI's own market reader; `GITHUB_TOKEN` when set) and keeps the answer ten minutes per instance, and the CDN keeps a market page an hour (`s-maxage=3600, stale-while-revalidate`), or a minute when GitHub did not answer. The catalog is bundled at deploy (`lib/catalog.ts`: `dist/manifest.json` through `parseCatalog`), so `/` and `/sheets` are cached for the deployment's life — each deployment has its own cache key.
- Deployment: Vercel follows `vercel.json` (`framework: null`, Bun `1.x`, the project's Root Directory `site`): the theme build, then `build.ts`, which writes the assets to `public/assets` and then the Build Output API directory `.vercel/output` that Vercel deploys as it stands (`output()`): `static/assets` for the CDN, content-hashed and `immutable` through a route header, and one Bun function, `functions/index.func`, the server bundled whole with Elysia inside, no `node_modules`. Under `framework: null` Vercel's `@vercel/static-build` runs the build command and takes `.vercel/output/config.json` as the deployment. Vercel's Elysia preset is not used: it compiles TypeScript itself, so `@/` paths, the root's `.ts` imports and Bun macros would not survive it, it finds its entry only in a file that imports `elysia` (so Elysia had to stay external), and it serves no `public/`, so every asset went through the function. `dev.ts` serves `/assets/*` itself with Elysia's `file()` and `no-store`. GitHub Pages keeps only `manifest.json` and the README's pictures (`mise run pages`).

## Gotchas

- A page wrapper that is a `grid` needs `grid-cols-[minmax(0,1fr)]`, or a child's min-content (a nowrap command, an `auto-fit` grid) widens the track past a phone's width; a `<button>` used as a grid container needs it too.
- A `.wear` root that changes palette calls `settle()` (`client/dom.ts`): for 650ms `data-settling` turns off every descendant's own transition, so text and borders follow the root's 0.6s palette fade exactly instead of chasing it. A TerminalPreview inside a worn page takes `worn` and inherits the slots rather than setting them, or it snaps while the page fades. `applyMode` (`client/theme-mode.ts`) likewise suppresses transitions for one frame when light/dark flips.
- `cn` (`lib/utils.ts`) extends tailwind-merge with the custom text sizes (`2xs`, `code`, `display-*`). Add any new `--text-*` there, or tailwind-merge takes it for a color and drops it when a `text-<color>` follows.
- Two TypeScript programs: `tsconfig.json` (the server and the shared code: `esnext` and Bun's types, no DOM) and `client/tsconfig.json` (the DOM, no Bun). Client code never imports `lib/catalog.ts`, `lib/markets.ts` or the root's `src/` — a type-only import still pulls a module into the program — and shared code (`components/`, `lib/`) touches neither `document` nor `Bun`.
- `xss-scan` takes `.map()` over an array that came from a JSON import for unescaped content; give the array a typed constant first (`FONTS` in `app/document.tsx`).
- JetBrains Mono's subsets keep every OpenType feature (`subset-font`'s default): `body`'s `font-feature-settings` (`cv02`, `cv03`, `cv04`, `cv11`, `ss01`, meant for Inter) is inherited by the mono text too, and JetBrains Mono has those features, so a subset that dropped them would draw other glyphs (`l.cv01`, `t.cv02`).
- The mono subsets cover every code point between them, with no catch-all face holding the whole font: a character the font lacks (☆ in `Lucky☆Star`) falls through every face whose range claims it, and a catch-all face is fetched whole just to find the glyph missing.
- The dev server's reload stream sends `: ping` every 5s: Bun closes a connection idle for 10s, and the page took the reconnect for a restart and reloaded.
- `site:dev` and `site:build` both write `site/public` and `site/assets.json`, and the dev server restarts when `assets.json` changes and rebuilds in dev mode — stop it before a build.
- The function's `.vc-config.json` (`output()`) copies what Vercel's own Elysia preset writes for a Bun function — `runtime: bun1.x`, `launcherType: Nodejs` — since the Build Output API documents no Bun config. Before changing a field, compare it with what the preset writes now: `vercel build` on a copy without `framework: null` (the project's dashboard preset is Elysia) whose entry, named by `outputDirectory`, imports `elysia`. Leave `architecture` out: a local build fills in the machine's own.
