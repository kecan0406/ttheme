# site/

## Conventions

- The design system is the Design System artifact https://claude.ai/artifact/D3TtwiZtWyM175ydwyWCyv — read its README before styling anything. `app/globals.css` is its code form.
- `site/` is an Elysia 2 app (`elysia` pinned to `2.0.0-beta.26` — a beta, so a bump is a deliberate step) that renders KitaJS JSX (`@kitajs/html`, the `jsxImportSource` in `tsconfig.json`) to strings: there is no React and no client framework. `app/site.tsx` holds the routes and the 404 and 500 handlers (`error('global', …)`, so they also answer paths no route matched), and every response goes through `page()` (`app/document.tsx`: the document, its status, its `cache-control` and an `etag` hashed from its bytes, which Vercel's CDN answers a browser's revalidation with as 304, a cache miss included) — `@elysia/html` is not used because its `mapResponse` is plugin-scoped and never reaches the outer app's 404 and 500. `server.ts` is Vercel's entry (`export default`; Vercel refuses `listen`), `dev.ts` the local server; both `use(autoHead())` (`elysia/auto-head`) first, since Elysia 2 answers `HEAD` only through it, and without it every page and the `og:image` answered a link preview's or a monitor's `HEAD` with 404.
- UI parts live in `components/ui/*`: KitaJS components whose looks are `cva` variants in their own file, never a long `class` passed from a feature component. Every part renders `data-slot` (and `data-variant`/`data-size`) and carries no `dark:` variants — tokens do the theming. Behavior comes from native elements, not a library: `Dialog` is a `<dialog>` opened with `showModal()` (focus trap, Esc, `::backdrop`; `:root:has(dialog:modal)` locks the page's scroll), a `ToggleGroup` is a radio group (`has-checked:` styles, arrow keys for free; its `underline` variant draws tabs), `TabsList` a `role="tablist"` whose keys `client/tabs.ts` moves, `ScrollArea` a native overflow box. A toggle that only picks which panel shows needs no script: the palette page's install step and scene are radio groups whose section is a named `group`, and each panel is `hidden` with a `group-has-[input[value=…]:checked]/<group>:` variant, spelled out per value since Tailwind only generates classes it finds whole in the source. Icons are `lucide` nodes drawn by `Icon` (`lib/icons.tsx`).
- Interactivity is vanilla TypeScript in `client/`, bundled by `Bun.build` into one module: each page's widget is a custom element (`lead-showcase`, `facet-ground`, `sheet-browser`, `share-sheet`, `marketplace-board`, `theme-toggle`, `sparkle-burst`, `kaomoji-rain`; declared for JSX in `custom-elements.d.ts`) that reads its data from a `<script type="application/json">` the server wrote with `json()` (`lib/render.ts`, which escapes `<`, `>` and `&`), and re-renders a changed fragment with the same KitaJS component the server used (`html()`, then `fill`/`swap` from `client/dom.ts`), so every piece of markup has one implementation. A copy button is any `[data-copy]` button, handled by one delegated listener (`client/copy.ts`).
- KitaJS escapes attributes but not children: a string child takes `safe` on its element, or `escapeHtml()` when it is a component's child, and `xss-scan` (`@kitajs/ts-html-plugin`, run by `site:build`) fails otherwise — marketplace data comes from anyone's repository. Both KitaJS packages are pinned to their 5.0 prereleases, since 4.x's `xss-scan` exited 0 when it crashed and `site:build` passed unscanned; 5.0 needs TypeScript 6, so `site/` stays on 6 and Dependabot skips TypeScript's majors there until the plugin reads 7's API. An `aria-*` that must read `false` is written `String(value)`, since KitaJS drops a `false` attribute.
- Tokens use shadcn's vocabulary plus `soft-foreground`, `faint-foreground`, `success`, `warning`, `overlay`, `glass`, `glass-panel`: there is no light or dark mode: `:root` itself wears a palette — `globals.css` maps every token onto the slots `--bg`, `--fg`, `--cu`, `--se` and `--a0`–`--a15`, `<html style>` sets them from the first lead (`fallback`, `lib/official.ts`) and `WEAR_SCRIPT` (`lib/wear.ts`), inline in the document's head, overrides them before first paint with the visitor's stored pick — so every page wears the palette chosen in the header. Shadows are the dark `--elevation-*` ones.
- Only the scale: text `2xs` 11 · `xs` 12 · `code` 12.5 · `sm` 13 · `base` 15 · `display-sm/md/lg` (fluid) and `display-xl` for the landing's hero only and `mega` for the landing footer's wordmark only, radius from `--radius: 10px` (sm 6 · md 8 · lg 10 · xl 14 · 2xl 18 · 3xl 22), spacing on Tailwind's 4px steps. `text-[13.5px]`, `gap-[9px]`, `rounded-[3px]` are off the system; arbitrary values are for layout tracks, breakpoints and blur only.
- Faces: `font-sans` Inter for UI, `font-display` `Nunito` → `Hiragino Maru Gothic ProN` → `BIZ UDGothic` for palette names, the wordmark and page titles at `font-black` (list rows `font-extrabold`), `font-mono` JetBrains Mono for commands, ids, hex values and terminals. Inter, Nunito and BIZ UDGothic come from Fontsource and JetBrains Mono from `app/fonts`, which `build.ts` cuts with `subset-font` into `unicode-range` blocks (`MONO_SUBSETS`: `core` — latin and the dingbats every mock terminal draws, ❯ ✓ ✗ ➜ —, arrows, math, technical, shapes, and `rest` for everything else), so a page downloads only the blocks its text uses — 72–80 KB of mono on each page instead of the whole 187 KB. Every font goes to `public/assets` under a content hash (woff2 only, never inlined into the CSS), its `@font-face` minified with the rest of the stylesheet, and only the latin Inter, Nunito 900 and the regular JetBrains Mono `core` are preloaded (preloading the bold `core` too moved LCP later on `/marketplace` and `/p/<code>`). BIZ UDGothic is the display stack's last fallback, reached only by Japanese and a few symbols (the kaomoji, ✦), and its 248 faces were two thirds of the stylesheet, so they live in their own `cjk` stylesheet that loads without blocking render (`media="print"` until it loads). Each face has a `* Fallback` face in `globals.css` carrying next/font's metric overrides, so nothing shifts when it loads.
- Every page, the landing included, lies on the facet ground (`components/facet-ground.tsx`, which `Document` puts first in `<body>`, `client/facet-ground.ts`, `lib/facets.ts`): a fixed field of low-poly triangles behind the page, drawn on the server as SVG with each facet's tint, its light from a fixed lamp and its centre (`lib/facets.ts`), the rest done by CSS: a facet is `--bg` mixed 6–16% toward one of the signature colors and lit toward `--fg`, so it is right before any script runs and follows the palette through the slots like every other part, under each page's `ground` wash, and a scroll-driven animation drifts it at a fifth of the scroll; the lamp is a copy of the mesh with every facet lit (`--near: 1`), which `client/facet-ground.ts` clones on the first mouse or pen move and shows through a soft round mask that follows the pointer by `translate` while the copy inside moves the other way, so moving it repaints nothing (a custom property changed on the SVG or above it repaints every facet, 30–50 ms a frame); when `show()` dispatches `SHOW_EVENT`, before it changes the slots, the script writes the old slots (`--was-*`) and where the wave starts (`--ox`, `--oy`: the last press, the palette on show — the landing's preview, the sheets page's session — or the middle) on the element and flips `data-turn` between `a` and `b`, which restarts a keyframe animation on every facet, delayed by its distance (`hypot()`), that turns it over and swaps the old slots for the new at its midpoint, the whole field within about the slots' fade; under reduced motion it stays still, and without hover there is no lamp. Every page but the landing stays at this soft level and nothing louder: cards and the dialog `rounded-3xl` (22px), buttons `rounded-full`, inputs and command rows `rounded-lg`; neutrals are mixes of the worn palette; `ease-spring` (a `linear()` spring with a `cubic-bezier` fallback) only on a card's `animate-enter` and press, never on hover; nav, labels and toggles lowercase; a kaomoji only in a passing state (`copied (・ω・)`, an empty result, no such marketplace), one per view, never in a heading, doc or error.
- Routes: `/` the landing (`components/home.tsx`), `/sheets` a palette browser (`components/sheets.tsx`: the page wears the palette, a centered name with prev/next and ←/→, the tabbed TerminalWindow, a `ttheme use` row, a collapsible "slots and contrast" glass panel built from `components/palette-parts.tsx`, and a sticky glass filmstrip of every palette grouped by catalog that keeps the current one centered; there is no picture/backdrop view any more), `/marketplace`, `/marketplace/<marketplace>` (`official` or `owner@name`, `marketplacePath`) and `/marketplace/<marketplace>/<palette>` (`palettePath`), and `/p/<code>`, the page a share link opens (`components/share-page.tsx`: the palette read from the code in the address by the CLI's own `readCode` — nothing is stored —, laid out as a builder on the site's own tokens and never worn: a sidebar of the slots — the four base rows, the ANSI colors as normal/bright pairs, the gate with the slots a missed rule names — and the about tab, beside the palette editor's own mock window, whose `zsh`, `nvim` and `htop` tabs `paneLines` draws at a fixed grid (`GRID`, 120×34) that the window scales between 13px and 11px and crops below that, zsh keeping its last lines and the others their footers (`footerRows`); every run carries its text and ground slots (`data-t`, `data-g`). `share-sheet` adds the inspector (a run's slots and contrast on hover or tap, pinned by a click), the slot popover — the editor's plane and hue track (`reach`, `shareOf`, `RAINBOW_L`/`RAINBOW_C`), its value formats (`colorText`), `slotChecks`, `slotUse`, the run counts per tab and "show where it's used", which dims every run that draws with neither slot — and the add popover with the `ttheme add` and `init` rows; the pictures show as links to their posts, never the pictures themselves — and, once `share-sheet` has fetched `/p/<code>/credits.json` (`lib/credits.ts`: `postCredit` from `src/artists.ts` per picture, 8 s each; a day at the CDN, a minute when a lookup failed), with who drew each, the artwork's page and the artists' own pages, which `PictureRows` (`components/picture-list.tsx`, shared with the client) draws in place. `lib/share.ts` computes all of it on the server with the CLI's own functions and hands the browser a `ShareView` (`lib/share-view.ts`)), with `/p/<code>/card.png` as its `og:image` (`lib/card.ts`: the signature, a few bars of code and the sixteen ANSI colors, drawn with `encodeRgb`, no text); a code that does not read answers 404 with the reason. The landing is the one page allowed a louder layer on top, and only there: the `pop` Button (a 4px lip, one per page), the `sticker` Badge, `sparkle-burst` on the hero name, the dancing ANSI pills (`animate-dance`), the preview's squish as it fades in on a palette change, color emoji on the feature cards, and `kaomoji-rain` (type `uwu`). It cycles the catalog leads every 4s until a visitor picks a palette (never under reduced motion), and it wears the site palette like every other page.
- `<html>` wears the site palette, except on a palette page (`/marketplace/<marketplace>/<palette>`), which wears its own: `page()` takes `wear` and `Document` writes that palette on `<html>` in place of the first lead and leaves `WEAR_SCRIPT` out, so the stored pick never covers it, and nothing is stored (a pick in the header still shows at once and is stored, as everywhere). `.wear` makes any other element wear one: `wearVars(theme)` (`lib/wear.ts`) is the raw slots plus `--wear-name` and `--sg0`–`--sg2` (the signature), `rootStyle` writes them on `<html>` and `show()` (`client/wear.ts`) on the client, and the picker's trigger is a fixed 200px pill (the name on the left, truncated, then the signature dots and a chevron) that draws its name with `content: var(--wear-name)`, so it is right before any script runs and never changes width with the name (the longest official name, `determination`, is 94px at `text-sm`; its screen-reader label is the hidden word `palette`). Tailwind's `max-[Npx]` is exclusive (`width < N`) and `min-[Npx]` inclusive, so the header pairs `max-[720px]` with `min-[720px]`. `TerminalPreview`, the palette page's preview window and the mock window of `/p/<code>` set the slots on themselves only, and a row's color chip paints the palette's colors inline.
- The site palette is picked in the header's `palette-picker` (`components/palette-picker.tsx`, `client/palette-picker.tsx`): it lists the official palettes from `/palettes.json` (every `Theme`, fetched when the trigger is hovered, focused or opened, cached for the deployment) and `choose()` (`client/wear.ts`) stores the pick in `localStorage` (`WEAR_KEY`: the vars, whether the palette is light, and the `Theme`), dispatches `ttheme:wear` and, unless a listener took it, shows it on `<html>`. `lead-showcase` and `sheet-browser` take the event (`onWear`) to draw their own fragments. The landing cycles the leads every 4s only while nothing is stored, and a pick anywhere stops it for good; the visitor's own moves on the landing and `/sheets` are remembered (`remember`) and the cycle's are not; each opens on the stored palette (`recall`), drawn at once when it differs from the server's first lead.
- One header and one footer for every page but `/p/<code>` (whose builder bar keeps its own tools): `SiteHeader` (`components/site-header.tsx`) is the wordmark and a pill track of `sheets` and `marketplace` (the current page a card pill) on the left, `github` and the palette picker on the right, and below 720px the right side is the `#site-menu` popover behind a menu button (one DOM element, shown inline above that width by author styles over the popover UA rule, so the picker exists once). `SiteFooter` (`components/site-footer.tsx`) is the same everywhere: a brand column (wordmark, tagline, `Facts` counts), the three link columns and a bar with the MIT line and `v<version>`; `Facts` (`lib/facts.ts`) is built once in `app/site.tsx` from the official palettes and the root `package.json` and passed down as a prop, since `home.tsx` and `sheets.tsx` are reached by the client program and `components/` cannot import `lib/official.ts`. Its `ribbon` is a 6px strip of the sixteen ANSI colors on its top edge, only where a palette is on show: a palette page passes that palette (with an `ansi 0–15 · <name>` caption) and `/sheets` passes `'worn'` (the site palette's `--a0`–`--a15`, so it follows each change); the list pages, store pages and the 404 have none and open with a hairline. The landing alone passes `landing`: the tagline in place of the brand column and, under the links, `ttheme` in `text-mega` (`--text-mega`, 88–300px) cropped at the top and tinted from `primary` at 16%, with the sixteen colors as `animate-dance` pills in front.
- The marketplace pages are a list of the marketplaces, a page per marketplace and a page per palette, inside `MarketplaceFrame` (`components/marketplace-frame.tsx`: the header, a `<main>`, `Crumbs` and `SiteFooter`); a marketplace is the unit everywhere, and a catalog shows only as a section of its marketplace's page and as a palette's tag. `/marketplace` (`components/marketplace-page.tsx`) is the title beside a lede counting the palettes and marketplaces, `try it now` and the terminals, then `marketplace-board` (`components/marketplace-board.tsx`, `client/marketplace-board.ts`): a search that `/` focuses, source tabs counting the marketplaces that still hold a palette the query leaves (`shelvesMatching`), and a row per marketplace (`Shelf`, `lib/gallery.ts`: official first, then each marketplace in the order GitHub's search gives) with its source, about, palette count and gate. A row is a `<details>`, closed until opened, holding a link to the marketplace's page and its palettes as `PaletteRow`s (`components/palette-rows.tsx`: its name, its catalog or a marketplace palette's full id, its color chip — the signature over the sixteen ANSI colors on its background — and the gate as passed/total, linking to its page); while a query filters, every marketplace with a match opens and counts `n of N`, and clearing it puts back the rows the visitor opened. `/marketplace/<marketplace>` (`components/marketplace-store.tsx`) is one marketplace: its breadcrumb, title, facts, about and the command that adds it, then a section per catalog (`catalogAnchor`) of rows. `/marketplace/<marketplace>/<palette>` (`components/palette-page.tsx`) is one palette: its breadcrumb (marketplace, its marketplace, the palette), title and tags (its catalog links to the catalog's section), then the install step (add, use, first time), the preview window with its scene, the twenty slots to copy and the rest of its catalog, beside a sidebar of its signature, marketplace, catalog, ANSI source, background, a marketplace's GitHub facts and the gate's rules. An unknown marketplace or palette answers 404. Marketplaces are read when a request needs them: `lib/marketplaces.ts` calls `showcase()` (`src/showcase.ts`: GitHub's topic search for `ttheme-marketplace` and each hit's archive, read by the CLI's own marketplace reader; `GITHUB_TOKEN` when set) and keeps the answer ten minutes per instance, and the CDN keeps a marketplace page an hour (`s-maxage=3600, stale-while-revalidate`), or a minute when GitHub did not answer. The official marketplace is bundled at deploy (`lib/official.ts`: `dist/manifest.json` through `parseManifest`), so `/`, `/sheets`, `/marketplace/official` and its palettes' pages are cached for the deployment's life — each deployment has its own cache key.
- Deployment: Vercel follows `vercel.json` (`framework: null`, Bun `1.x`, the project's Root Directory `site`): the theme build, then `build.ts`, which writes the assets to `public/assets` and then the Build Output API directory `.vercel/output` that Vercel deploys as it stands (`output()`): `static/assets` for the CDN, content-hashed and `immutable` through a route header, and one Bun function, `functions/index.func`, the server bundled whole with Elysia inside, no `node_modules`. Under `framework: null` Vercel's `@vercel/static-build` runs the build command and takes `.vercel/output/config.json` as the deployment. Vercel's Elysia preset is not used: it compiles TypeScript itself, so `@/` paths, the root's `.ts` imports and Bun macros would not survive it, it finds its entry only in a file that imports `elysia` (so Elysia had to stay external), and it serves no `public/`, so every asset went through the function. `dev.ts` serves `/assets/*` itself with Elysia's `file()` and `no-store`. GitHub Pages keeps only `manifest.json` and the README's pictures (`mise run pages`).

## Gotchas

- A page wrapper that is a `grid` needs `grid-cols-[minmax(0,1fr)]`, or a child's min-content (a nowrap command, an `auto-fit` grid) widens the track past a phone's width; a `<button>` used as a grid container needs it too.
- `<html>` or a `.wear` root that changes palette fades its slots for 0.4s and calls `settle()` (`client/dom.ts`): for 450ms `data-settling` turns off every descendant's own transition, so text and borders follow the root's fade exactly instead of chasing it. A TerminalPreview inside a worn page takes `worn` and inherits the slots rather than setting them, or it snaps while the page fades. The change itself runs inside `fadeThrough()` (`client/dom.ts`, one `document.startViewTransition`): every fragment whose text the palette changes — `lead-showcase`'s name, title, preview and command, `sheet-browser`'s heading, session pane, command, the details' two columns and the selected tab's label — carries a `view-transition-name` (`globals.css`, scoped to its element; the tab's is inline and keyed by its id, so selecting another tab never slides a label across), and leaves in its old colors within 0.12s before the new one fades in over a palette already three quarters arrived, so no frame shows new text in the old colors or two texts over each other. Nothing else is captured: `:root` takes `view-transition-name: none` and `::view-transition` `pointer-events: none`, since a captured element takes no clicks while it animates and a captured root or page wrapper swallowed every click while it ran. The transition layer draws above the whole page, so `fadeThrough` clips it (`--clear-top`, `--clear-bottom`) to the band between the `[data-sticky]` bars, which a fragment passing beneath them would otherwise cover, and a fragment a rounded ancestor clips (`lead-preview`, `sheet-session`) gets that radius on its group. The update runs a frame later, so it reads the state when it runs, and a change while one runs skips that one to its end. Without the API or under reduced motion the text changes at once.
- `cn` (`lib/utils.ts`) extends tailwind-merge with the custom text sizes (`2xs`, `code`, `display-*`, `mega`). Add any new `--text-*` there, or tailwind-merge takes it for a color and drops it when a `text-<color>` follows.
- Two TypeScript programs: `tsconfig.json` (the server and the shared code: `esnext` and Bun's types, no DOM) and `client/tsconfig.json` (the DOM, no Bun). Client code never imports `lib/official.ts`, `lib/marketplaces.ts` or the root's `src/` — a type-only import still pulls a module into the program — and shared code (`components/`, `lib/`) touches neither `document` nor `Bun`.
- `xss-scan` takes `.map()` over an array that came from a JSON import for unescaped content; give the array a typed constant first (`FONTS` in `app/document.tsx`).
- JetBrains Mono's subsets keep every OpenType feature (`subset-font`'s default): `body`'s `font-feature-settings` (`cv02`, `cv03`, `cv04`, `cv11`, `ss01`, meant for Inter) is inherited by the mono text too, and JetBrains Mono has those features, so a subset that dropped them would draw other glyphs (`l.cv01`, `t.cv02`).
- The mono subsets cover every code point between them, with no catch-all face holding the whole font: a character the font lacks (☆ in `Lucky☆Star`) falls through every face whose range claims it, and a catch-all face is fetched whole just to find the glyph missing.
- The dev server's reload stream sends `: ping` every 5s: Bun closes a connection idle for 10s, and the page took the reconnect for a restart and reloaded.
- `site:dev` and `site:build` both write `site/public` and `site/assets.json`, and the dev server restarts when `assets.json` changes and rebuilds in dev mode — stop it before a build.
- The function's `.vc-config.json` (`output()`) copies what Vercel's own Elysia preset writes for a Bun function — `runtime: bun1.x`, `launcherType: Nodejs` — since the Build Output API documents no Bun config. Before changing a field, compare it with what the preset writes now: `vercel build` on a copy without `framework: null` (the project's dashboard preset is Elysia) whose entry, named by `outputDirectory`, imports `elysia`. Leave `architecture` out: a local build fills in the machine's own.
